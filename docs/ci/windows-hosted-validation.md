# Windows hosted validation

The first hosted run installed DSH and passed the offline doctor on Windows x64. The PowerShell 5.1 harness stopped producing output at StartupProviderIsolation and was cancelled by the 40-minute job deadline. Its logs did not identify which operation blocked. The PowerShell 7 harness never started.

The setup-upgrade fixture now supplies the POSIX entry point required by the real Windows installer. The process-identity probe uses the .NET Framework command-line property and checks the exact argument vector, including a space and an empty argument. The credential example and redaction probes tolerate the Windows line ending and JSON escape representations, respectively.

Windows PowerShell 5.1 and 7 now run in independent matrix jobs with separate clean installs, validated reports, and security completion proofs. The aggregate gate requires both, along with Ubuntu, macOS, and source contracts.

The harness streams child output, records the active suite and completed rows in a progress JSON file, and uses a child-process deadline. A timeout or launch failure is INCOMPLETE. Normal suite failures and timeouts can still upload diagnostics and produce a final failed report. The startup-provider fixture records fixture preparation, launch, readiness and process exit as separate stages. Its subsequent launcher calls and HTTP probes are bounded, and launcher stdout and stderr are stored in the CI artifact directory.

Run 42495047797 produced both 104-row Windows reports. Each had 92 passes, 11 failures, and one incomplete suite. SetupUpgrade and PlatformPortability passed on both hosts. StartupProviderIsolation passed on PowerShell 7. On PowerShell 5.1 both initial launches reached READY, and the reuse launcher logged that it found the existing runtime. The combined exit-code and PID assertion failed. The follow-up retains the process handle and logs those fields separately. The first run's silent stall remains unattributed.

The real-host security matrix executed on both Windows jobs and was marked INCOMPLETE when it exceeded the original eight-minute suite deadline. The raw logs show recurring intervals of about 20 seconds between case results. Windows now has a 16-minute default watchdog for that suite and logs slow probe durations. The overall job deadline, the 104-suite inventory, the 29 real-host cases, and the required completion marker are unchanged.

Run 42591204390 confirmed StartupProviderIsolation passes on both Windows hosts, including PowerShell 5.1 launcher exit 0 and matching READY PID. The PowerShell 7 report had 100 passes, three failures, and an incomplete boundary suite. PowerShell 5.1 reached the boundary suite but the global job deadline cancelled it before a final report could upload. The boundary trace measured repeated 20–23 second probes and one 224-second pre-step on PowerShell 7. The fixture now provisions test-owned Windows profile directories and measures bare PowerShell startup to help isolate that cost. The credential allowlist, real host, and assertions remain in force.

Run 42596545664 measured bare Windows PowerShell startup at 141 ms on the PowerShell 7 lane, while real boundary probes still took about 23 seconds each. It also exposed missing Get-FileHash in the Windows PowerShell children launched from the PowerShell 7 capture test. The capture test scopes those children to the Windows PowerShell built-in module directory. The boundary fixture also uses the built-in module directory and measures a command that requires module discovery. Its startup probe uses the shared platform resolver to satisfy the portability scanner.

Run 42601602714 passed source contracts and all 104 suites on Linux and macOS. Both Windows hosts completed all 103 other production suites successfully, with only the real-host boundary suite marked INCOMPLETE at 16 minutes. Its startup command with module discovery took 23–29 seconds. Each Windows host now has two independently required clean-install jobs. The general job validates its exact 103-suite inventory, and the security job validates its single suite and required marker. The inventories are disjoint and together cover all 104 production suites. The Windows security suite has a finite 25-minute watchdog in its dedicated job. The 40-minute job cap and POSIX production lanes are unchanged.

Run 42607085007 passed both general Windows shards and ran all 29 boundary cases on both Windows security shards. Each security shard then failed during fixture cleanup with EPERM, before emitting its completion marker. Cleanup now unlinks the two fixture-owned app/runtime junctions before recursively removing the remaining temporary tree, retries transient deletion errors, and reports surviving fixture entries on failure. Successful cleanup remains required before the completion marker.

Run 42611465527 again recorded 29 cases on each Windows security shard, then exhausted the watchdog during in-process fixture deletion. The suite now waits for the real host worker to exit before the parent deletes its junctions and temporary tree. The PowerShell 5.1 general shard also identified a fake ADB trace-file race during device discovery. Device discovery no longer writes to the shared trace, which still records the actual capture critical section.

Run 42615324942 passed both general Windows shards, both POSIX jobs, and the Windows PowerShell 7 security shard with all 29 cases and successful cleanup. The Windows PowerShell 5.1 security shard stopped before the DSH boot on a standalone PowerShell timing probe. That diagnostic is removed now that it has measured module-discovery latency. Real host startup, probe timing, and the mandatory completion checks remain.
