## 1. Architecture

```
React + TS  ->  typed Tauri commands / Channel  ->  nexus-client v1  ->  daemon IPC  ->  Kernel
apps/nexus-desktop/src        src-tauri/src/{lib,backend,dto}.rs          native/nexus-client
```

- `src-tauri` is its own cargo workspace (path dep on `nexus-client`); `native/Cargo.lock` is untouched.
- `backend.rs` is pure adapter logic (no Tauri types) and fail-closed: protocol mismatch, missing `state` or
  `dispatchEnabled` => `malformed`; daemon claiming dispatch enabled => `unsafe`.
- Frontend capability set = 7 commands: `app_info`, `runtime_status`, `list_tasks`, `task_journal`,
  `model_catalog`, `live_blockers`, `run_mock`. No fs/shell/http/opener plugin. CSP `default-src 'self'`.
- Native core changes (minimal, read-only/mock): `nexus-client` gained `run_mock_streaming` (ordered
  step/stream progress, text and usage now derived from the real stream events instead of hardcoded values,
  real verification checks), and `journal_for_task` (see finding F1).

## 9. Per-task conversation history (added requirement)

### 9.1 Historical availability assessment (measured, this machine)

Sources inspected: `.ai-harness/state/tasks.json`, `.ai-harness/runs/<TASK>/attempts.jsonl` (+ manifest),
`~/.local/share/nexus/data/sessions/<workspace>/<session>/session.jsonl.zstd` (multi-frame zstd JSONL).

| Fact | Result |
|---|---|
| Messages persisted? | Yes. Session logs hold `user/message`, `assistant/message`, `tool/call`, `tool/result`, `turn/*`, `request/header`, `llm/retry`, chunks |
| Attempt journal join keys | `taskInstanceId` + `attemptId` + `sessionId` + `startedByTurn` + `workspace` (70 started attempts) |
| Session file found for attempt | 70 / 70 |
| In-record binding message names the same task instance | 69 / 70 (1 refused) |
| Sessions bound to more than one task instance | 0 |
| Instances with a verifiable conversation | 58 / 59 |
| Records produced (all 59) | 147 user messages, 1813 assistant messages, 22,919 tool events, 548 redactions, 171 truncated fields |
| Decode cost | ~190 ms per task on average (release); done off the UI thread |

Provenance mapping: `taskInstanceId` (immutable identity) -> attempt (`attemptId`, sequence, `startedByTurn`)
-> `sessionId` -> session log. Attempt attribution of each message uses turn ranges
(`startedByTurn` of attempt k up to the next attempt). The display id (`TASK-xxxx`) is only a label and must
equal the run directory name; it is never a join key. Timestamps are never used to join.

Join rules enforced (all required): journal record names the instance id and its display id equals the run
dir; session header id equals the journal session id and `cwd` equals the attempt workspace; a Controller
binding message in the session names the same instance and no binding names another. Otherwise the
session yields no events and the refusal reason is shown under Provenance.

Coverage limits (not recoverable or not shown):
- Tasks with no attempt record (never started) have no conversation.
- Reasoning blocks are withheld (text is empty/encrypted in the logs; replay state is never surfaced).
- Nested `run_code` sub-dispatch records are counted, not rendered.
- The full provider message array is not recorded verbatim; Model I/O shows only the recorded request
  header (provider, model, effort, system prompt, tool names, context window). It is never reconstructed.
- Delegated child sessions (`delegationDepth > 0`) were not examined or joined.
- Display text is capped at 32,000 chars per record (tool input 16,000), flagged `truncated` with original
  length; credentials are replaced with visible `[REDACTED:*]` markers and counted.
- One of 59 instances is refused by the binding check; sessions deleted from disk are reported as
  unavailable. Exact copy shown when nothing exists: "Conversation history was not recorded for this task."

### 9.2 Transcript contract `nexus.transcript/v1` (crate `native/nexus-transcript`)

Additive JSON record `TranscriptEventV1`: `eventId`, `messageId`, `revision`, `seq` (display position),
`revisionSeq` (store cursor), `taskInstanceId`, `displayTaskId`, `attemptId`, `sessionId`, `turn`, `kind`
(user-message | controller-message | assistant-message | tool-call | tool-result | status | error |
model-handoff), `speaker` (user | orchestrator | worker | reviewer | tool | runtime | controller), `actor`
{agent, model, provider} (recorded values only), `inputClass` (user-authored | controller-compiled |
runtime-injected | tool-output | model-generated | system), `timestampMs`, `state` (partial | final |
interrupted), `text`/tool fields, `source` (native-store | dsh-session-log | mock-fixture), `recording`
(recorded | assembled-from-chunks), `redactions`, `truncated`, `originalLen`.

Durable store: one append-only JSONL file per task instance (`<data>/nexus/native/transcripts`, dir 0700),
each line hash-chained to the previous one, fsync per append, exclusive file lock. Duplicate id+revision with
identical content is an idempotent no-op; different content is a conflict. A torn line is skipped; a broken
chain fails closed (nothing after the break is trusted). Records naming another task are refused on write
and distrusted on read. Historical DSH records are read in place and cannot be copied into the store.
Writers: only the backend process (`run_mock_recorded` today). The renderer has no write command.

### 10.2 Security audit and fixes

Defects found and fixed (each has a regression test):

| # | Defect | Fix | Test |
|---|---|---|---|
| S1 | Symlinks were followed for session dirs/files, run dirs and `attempts.jsonl` | `symlink_metadata`-based plain file/dir checks everywhere on the read path | `symlinked_session_directory/file/run_directory...` |
| S2 | Compressed log read fully into memory with no size cap | `max_compressed` (64 MiB) checked before reading | `oversized_compressed_log_is_refused...` |
| S3 | A truncated/corrupt final frame discarded the whole log | decoded prefix is kept, note + invalid counter recorded | `truncated_frame_keeps_the_decoded_prefix...`, `garbage_log_is_unavailable...` |
| S4 | Unredacted free-form fields: agent/model/provider labels, tool names, call ids, error codes, turn-end kind, handoff text, request header provider/model/effort | `label()` clips to 80 chars and redacts every recorded identifier | `secrets_in_every_recorded_channel_are_redacted` |
| S5 | Redaction gaps: quoted values with spaces, URL userinfo, `sk_`/`rk_`/`ghs_`/`ghu_`/`glpat-`/`npm_`/`hf_` shapes, cookie/credential keys | extended rules | redact unit tests |
| S6 | Ledger task text (description, acceptance criteria, failure signatures) reached the renderer unredacted | redacted in the Tauri adapter | `ledger_text_is_redacted_before_reaching_the_renderer` |
| S7 | Per-line size, row count and attempt file size were unbounded | `max_line` 8 MiB, 2,000,000 rows, 4 MiB attempt file | `overlong_lines_are_skipped_and_counted` |
| S8 | Decompression bomb | output cap across all frames (`max_decompressed`, 256 MiB) | `decompression_bomb_is_bounded` (RLE frame) |

Confirmed OK: path traversal (task/session/display ids are matched against strict patterns before any path
is built; instance id re-validated in the daemon frame builder and the store), no HTML/Markdown execution
(inert React text nodes, no anchors; tested with script/javascript:/unterminated fence), private reasoning
(reasoning blocks and replay state are dropped in the adapter; asserted by
`reasoning_text_and_replay_state_never_leave_the_adapter`), Model I/O wording ("recorded request header...
full provider message array is not recorded verbatim ... never reconstructed", asserted on real data).

Remaining residual risks (accepted, documented): redaction is pattern-based and cannot recognise
arbitrary high-entropy secrets with no recognisable shape; pure-Rust zstd decode is CPU-bound for the
largest logs; the in-process cache holds up to 6 decoded histories.
