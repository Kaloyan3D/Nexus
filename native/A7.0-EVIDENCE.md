Design, audit and what changed: `native/docs/A7.0-AUTONOMY-REFACTOR.md`.
Durable evidence (run records, final texts, patches): `native/docs/acceptance/a70/`.

Everything is **uncommitted**. Provider: real OpenCode Go (`opencode-go-native` / `muse-spark-1.3-contributor`) under the operator's standing development-test authorization, on disposable projects and on the operator's own Sentry repository (read-only task, isolated copy). Nothing was pushed, merged or deployed; nothing was installed system-wide.

Machine: Linux, Node 26 / npm 12, Python 3, .NET 10 SDK, Rust. **No Go, pnpm or yarn on this machine.**

## 1. Verdict

**All four hard scenarios (A–D) passed with durable evidence, through the real Desktop where required.** The remaining gaps are listed in §6; none of them is a failure of a required scenario, but they bound what can be claimed:

* Go support is implemented and unit-tested at the policy level but was **never run** (no Go toolchain here).
* pnpm/yarn workspaces were not exercised (npm only); a pnpm project installs with `npm install` and ignores `pnpm-lock.yaml`.
* One model, one machine, small sample sizes (§5). This is "demonstrated", not a completion-rate claim.
* Window screenshots of the Tauri window came out blank on this machine; the Desktop was verified through its DOM (§3), not through images.

## 4. What the real runs found (all fixed, each with a regression test or a real re-run)

1. Provider turn failures ended runs (`send-uncertain` after 19 tools; `payload-too-large` ×6 on a real audit because the raw-response bound was ~384 KiB) → recovery + interactive transport bounds.
2. A progress sentence accepted as "completed" (twice) → completion nudges.
3. Any command counted as a verification (`ls` ⇒ "verified-passed") → only build/test/check commands verify.
4. Desktop/CLI watchers restarted a *busy* runtime when its list call timed out, killing running tasks → idle-only replacement; `busy`/slow ≠ dead; watcher needs minutes of silence and a dead/hung process.
5. `intent-list` re-read every transcript (list > 10 s with 24 runs) and the broker allowed 16 connections → light list/status views, 128 connections.
6. Node/V8: address-space rlimit made WebAssembly fail; npm 12 blocked package install scripts (esbuild); `dotnet` needed `obj/` kept and no compiler server.
7. Daemon restart invalidated the broker's capability and killed in-flight steps → capability re-read, connect-time retry, daemon-only restart.
8. Source files *named* `provider-credentials.ts` were treated as secrets and silently excluded from the copy, which made a real audit report a "missing module" (a false finding) → code files that merely name the concept are readable; the agent is told the copy omits secrets.
9. The agent widened a task to fix unrelated failing tests → guidance + nudge wording.
10. Scratch files (`store.rs.new`) in a patch → delete + nudge.
11. Terminal-record annotations (`continued_as`, trusted-apply result) were silently dropped → `annotate`.
12. Strict-profile privacy regression caught by an existing test (prompt preview persisted) → interactive only.

## 6. Limits and caveats (honest)

* Sample sizes are small. Failures found in earlier runs were fixed and the *same* scenario repeated (the Sentry audit was run seven times before it produced a good report; B, C and D 3–4 times each). The listed runs are the passing ones plus the interrupted runs D/C needed; the failures in between are described in §4, not hidden.
* The weaker/"contributor" model sometimes narrates instead of acting, repeats itself, or hallucinates limits; the harness compensates (nudges, recovery) but quality is model-bound. The Sentry report is substantive but is a model's audit, not a verified security review; some of its findings are hypotheses it labels as such.
* Trusted workspace is "apply on completion", not live editing of the folder (by design, see the design doc).
* Go untested; pnpm/yarn absent; Windows/macOS not touched.
* Per-turn latency is dominated by the Controller bridge (one Node process per step) plus provider time; a 50-turn task takes 4–6 minutes.
* The interactive profile trusts the same OS user. The strict profile is the answer where that is not acceptable; it is unchanged and still tested.
