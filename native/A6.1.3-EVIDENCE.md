## Remaining limitations
1. Same-UID dev instance: the registry owner, daemon, broker and approver are one uid (the first live run is such an instance); distinct-uid isolation is proven by the userns suite incl. the new registry test (second-pass closure, `docs/A6.1.3-PROJECT-OPERATIONS.md` §1a).
2. GUI verification used programmatic interaction in the webview, not human clicks (see above).
3. The registry is unsigned by design (explained in the operations doc).
4. Desktop cannot show the project's disclosure text or restrictions per project beyond pin/scope/limits (they are printed by the CLI and the composer's terms).
5. Process allowlist unchanged: Rust and npm/tsc only; Python/Go/.NET/others need a separate security review. JS projects need pre-existing offline `node_modules`.
6. A copy younger than the run's end cannot be removed while the run is non-terminal, by design; a crashed broker leaves such a run non-terminal until startup recovery closes it.
7. `patch` refuses a diff larger than the daemon's 256 KiB / 200 file bound unless `--allow-truncated`.
