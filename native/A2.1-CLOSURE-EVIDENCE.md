## 2. Service identity and credential-handoff design

```text
nexusd (User=nexusd, SupplementaryGroups=nexus-issuer, UMask=0077)
  owns /var/lib/nexusd (0700): k.db, k.witness.db, daemon.lock, issuer.cap (0600)
  owns /run/nexusd (0750 nexusd:nexus-issuer): n.sock (0660), issuer.handoff (0640)
nexus-issuer: traverses /run/nexusd, connects n.sock, reads issuer.handoff.
  NEVER reads /var/lib/nexusd (cat/tee/ls all EACCES — multuid test 2).
  IPC auth = possession (HMAC key) + process identity (SO_PEERCRED allowlist).
nexus-untrusted: not in issuer group -> connect(2) fails EACCES (multuid test 3).
nexus-bystander (reference hostile): in group, NOT allowlisted -> connects,
  valid stolen HMAC still refused peer-unauthorized (multuid test 4).
```

Handoff lifecycle: written after bind (after `secure_socket_file`), content =
`key_hex()` of the incarnation key, overwritten every start (rotation proven
by multuid test 6 asserting `cap1 != cap2`), removed at shutdown alongside
the socket, scrubbed (unlinked) on any post-open failure. Key never logged;
status/readiness report only `capHandoff: true/false`.

Same-UID module confusion (hostile code inside the issuer process) remains
out of scope by design (A0.3 §A1 limitation, restated in every surface that
reports the gate). Path-swap races by group members are DoS-only (fail
closed, no privilege gain) and documented.

## 6. Remaining security limitations (actual, not boilerplate)

1. Container scope, stated precisely: the 8/8 proof ran in a disposable
   container sharing the host kernel — the UID/GID/`SO_PEERCRED`/DAC mechanisms
   are the production kernel paths, but the production host deployment
   configuration itself (systemd unit at `/var/lib/nexusd` + `/run/nexusd`
   with real service users) was NOT exercised here and must be verified on the
   target host before production sharing. This container proof must not be
   cited as proof of that host configuration.
2. Same-UID module confusion is unprevented by construction (pinned by
   `peer_credentials_report_uid_not_module_identity`).
3. Group-member DoS (socket-path swap, handoff rewrite races) fails closed
   but is not prevented; directory DAC assumes no broader re-exposure
   (ACLs, mounts, backups, volume sharing, root-equivalent peers).
4. Witness same-disk restore remains undetected by construction (A2.0 limit).
5. No cross-file atomicity / power-loss claims (A1.1 limits).
6. Readiness `transport` (incl. `socketShared: true`) is posture reporting,
   never an authorization token.
7. Numeric `--socket-group 0` (root group) is accepted as explicit selection;
   operators must not configure it (noted, not silently remapped).
