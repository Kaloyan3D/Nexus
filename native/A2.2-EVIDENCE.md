## 1. Phase 0 - A2.1 review fix (isolated, proven)

Finding: write_handoff_file opened the destination itself with O_TRUNC and
wrote the new key BEFORE ownership/type/permission validation (A2.1 F3 had
fixed only the post-close stat path). Reproduced with plain POSIX
semantics: truncating a pre-existing 0644 file briefly carries the new key
world-readable, and a hardlink alias reads the new bytes permanently (same
inode, old mode at write time).

Fix (nexus-daemon/src/auth.rs, handoff path only): fresh O_EXCL temp
sibling, 0600 then fchown(gid) then 0640, validation of the OPEN description
(regular file, daemon uid, socket gid, exact 0640, nlink == 1) BEFORE any
secret byte, then atomic rename over the destination. The old inode (and any
hardlink to it) keeps only stale bytes; a concurrently planted symlink is
REPLACED (rename never follows the destination) and refused by the
post-rename lstat gate. Symlinks, nonregular leaves (fifo/socket/dir), and
malformed key material are refused pre-write; stale temp siblings are
scrubbed (crash-rotation hygiene: unique names, no truncation, atomic
publish, best-effort dir fsync).

Regression tests (daemon lib 19 to 22, all green):
handoff_rotation_never_exposes_new_key_via_hardlink (fresh inode, stale
alias, repeatable rotation),
handoff_refuses_nonregular_leaf_and_leaves_no_temps,
handoff_scrubs_stale_temps_on_rotation. The eight multi-UID tests are
untouched (8 ignored on single-UID hosts by design; container proof stands).
A2.1 evidence carries a dated addendum distinguishing the committed baseline
from this fix.

## 2. Architecture review (ten answers, recorded)

1. Source of truth: Registry (JS) owns routing; Kernel owns acceptance;
   Controller owns attempts. nexus-model owns NOTHING durable: every
   preparation re-derives from pin plus sealed issuance plus snapshot.
2. Ownership: only writers are Registry (targets), Controller (attempts),
   daemon (capability files). The model crate never writes the store, never
   resolves models, never mints credentials.
3. Dependency direction: nexus-model depends on nexus-contracts only.
   Kernel and daemon do NOT depend on the model crate (no cycles, no second
   router).
4. Boundaries: explicit contracts (VerifiedExecutionPin, ExecutionTargetV2,
   ModelRequest, PreparedModelRequest, AttestedPreparedModelRequest,
   TerminalResponse). Forbidden to cross: live sockets, credentials inside
   messages or bytes or errors, endpoint strings from UI input, execution
   effects.
5. Failure semantics: 17 classified codes; unknown outcomes are
   send-uncertain or stream-partial; no retry anywhere; redirects refused;
   timeouts bounded; oversize fails closed. Each dependency failure
   (connect, flush, read, parse, revoke, cancel) maps to exactly one code.
6. State lifecycle: not_sent to send_uncertain to stream_partial to
   terminal_committed, plus recorded Failed/Uncertain outcomes in
   AttemptStore. No transition invents success; crash recovery re-derives
   uncertainty from a missing terminal.
7. Test seams: Transport trait (scripted MockTransport plus real-TCP
   HttpSseTransport against LocalMockServer); injectable CancellationToken,
   TransportLimits, Credential revocation; recorded fixtures.
8. Migration and compat: legacy issuance math byte-identical (same
   target_digest, snapshot_digest, issuance_id); the V2 extension is additive
   (extension_version 1) with its own digest bound into the pin. No existing
   contract changed; rollback is dropping the crate.
9. Observability: attempt states, send/read counters, server-side request
   line plus header presence (never secret values), fixture corpus with
   expected terminals.
10. Security: prepare sends nothing; dispatch needs attestation; binding
    pins the origin; credentials bypass bytes/errors/logs; redaction is
    centralized in ModelError::new (every path, tested per code).

## 4. Implementation (deliverables)

New crate native/nexus-model (synchronous port: the workspace has no async
runtime, and ordering semantics match the specified prepare/dispatch pair):

- target.rs: ExecutionTargetV2 over the preserved core: authoritative
  endpoint, billing, session, capabilities, context, connection
  (extension_version 1). Anything missing is target-incomplete; cross-field
  drift is wrong-target. No fallback exists to invent a field.
- pin.rs: VerifiedExecutionPin binds attempt plus sealed issuance plus
  snapshot plus extension digests; verify_against re-derives every digest
  and refuses post-pin Registry changes.
- request.rs: OpenCode-compatible input (messages/tools/overrides). Carries
  NO endpoint, model, or credential; overrides must equal the pin.
  stream=true is mandatory (terminal normalization requires SSE).
- prepare.rs: prepare() (no transport handle, sends nothing) emits exact
  canonical bytes plus digests; attest() re-verifies the full binding and
  issues the ONLY dispatch token (AttestedPreparedModelRequest has no other
  constructor: fields are private).
- transport.rs: Transport trait (send takes ONLY attested requests),
  Credential (redacted Debug, revocation), TransportBinding (origin pinned
  pre-connect), TransportLimits, TransportError with honest bytes_sent
  context, HttpSseTransport (exact request line, fixed header allowlist,
  3xx refused, bounded reads, complete-prefix retention on mid-stream cuts).
- sse.rs: strict Responses-compatible SSE parser plus StreamAssembler
  (ordered text/reasoning, per-item tool-fragment assembly as DATA never
executed, usage plus finish normalization, incremental bounds).
- stream.rs: AttemptTracker (explicit 4-state machine), AttemptStore
  (duplicate suppression, terminal replay without new bytes,
  continuation-required for uncertain outcomes), CancellationToken (checked
  pre-send, between events, mid-read; never terminal).
- runtime.rs: ModelRuntime plus OfflineModelRuntime: attestation coverage
  re-check, fresh-attempt gate, store preflight, credential/binding gates
  pre-send, exactly one send, bounded normalization. No retry on any path.
- testkit.rs (TEST-ONLY): MockTransport (9 scripts covering every failure
  class through the REAL parser), LocalMockServer (loopback TCP, records
  request line and header presence and body but never secret values, prompt
  shutdown, stall probe), fixture loader plus normalize_fixture.
- lib.rs: offline-scope documentation; production dispatch out of scope.

Recorded corpus native/test-vectors/model-transport/: basic-text,
reasoning-tool (3-frame argument assembly), interleaved-order (wire-order
plus unknown-type tolerance). Each carries expected text, reasoning, tools,
usage, finish. A wire-faithfulness test round-trips every fixture through
real loopback TCP and byte-compares against parser normalization.

## 6. Registry target field and provenance gap analysis

The authoritative V2 fields are currently TEST-ISSUED inside nexus-model
(test_target) and the conformance harness. The JS Registry issues no
endpoint, billing, session, or context metadata, and that gap is recorded
here rather than worked around:

- Endpoint origin/path/method: ABSENT from legacy core and from the JS
  issuer (no such metadata by construction). A2.2: test-issued only.
- Billing tier plus data-use provenance: legacy core has only an optional
  dataUseTier; the JS issuer passes it through with no tier. A2.2:
  mandatory test-issued BillingProvenance.
- Capability set: legacy requiredCapabilities is request-side, not an
  authoritative grant. A2.2: non-empty test-issued set.
- Context window: ABSENT everywhere. A2.2: test-issued tokens > 0.
- Session binding (x-opencode-session): ABSENT everywhere. A2.2:
  test-issued stable id, header-observed.
- Connection binding: connectionId exists in core and issuer; the A2.2
  credential itself is kept outside bytes entirely.
- Model/route/provider/role/mode identity: PRESENT and sealed end to end;
  preserved byte-for-byte (no issuance math changed).

Closing the gap (Registry-issued V2 with snapshot binding and
issuance-key sealing) is an explicit execution-readiness item, not claimed

## 11. Final audit (independent review follow-up)

Reviewed baseline: 5cd28eee plus the uncommitted A2.2 tree (nexus-model,
handoff fix, fixtures, sections 1-10 of this report). Method: line-by-line
read of every nexus-model module, the handoff publish path, the Registry
issuer/transport contracts, live probing of failure paths, and official
rust-genai documentation (docs.rs description, upstream README, retry
policy doc, workspace manifest).

Findings fixed (each with a failing-first test):

- F1 (header injection via target strings, CONFIRMED): endpoint origin,
  path, and session id reached the HTTP head without control-character
  validation, permitting request smuggling through a hostile Registry
  value. Fix: visible-ASCII-only rule (is_wire_safe) enforced in
  target.rs for origin/path/session plus host re-check in split_origin.
  Test audit_inject header_injection_strings_are_not_executable (6 cases).
  The test caught a first-version hole (non-ASCII admitted) before pass.
- F2 (duplicate provider completion last-wins, CONFIRMED): a second
  response.completed silently overwrote the first. Fix: fail closed with
  sse-malformed (duplicate completion refused, uncertain recorded, no
  retry). Test audit_sse duplicate_provider_completion_is_refused, proven
  red with the guard disabled and green with it.
- F3 (empty data frames refused, CONFIRMED): legal SSE keepalive padding
  (empty data:) failed the strict parser. Fix: ignore empty payloads and
  colon comments (content frames stay strict). Test audit_sse
  keepalive_frames_do_not_break_normalization.
- F4 (transport-level binding missing, CONFIRMED BY INSPECTION): only the
  runtime checked the endpoint binding, so a direct Transport::send caller
  could steer the networked transport anywhere. Fix: HttpSseTransport now
  owns its TransportBinding (constructor argument) and refuses mismatched
  origins pre-connect; the runtime gate remains as a second check. Test
  audit_trust networked_transport_enforces_its_own_binding (0 server
  connections on refusal). Existing conformance call sites updated.
- F5 (attestation overstated, CLASSIFICATION): pin/attest prove
  self-consistency of presented bytes but verify no kernel HMAC seal, no
  lease currency, and no Registry signature: a fabricated self-consistent
  chain attests structurally. Fix: documented as offline structural
  verification in pin.rs, prepare.rs, runtime.rs, and lib-adjacent docs,
  plus a boundary-pinning test (audit_trust
  structural_attestation_is_not_production_authorization) proving
  structural success never enables dispatch. Production authorization
  (seal plus live lease plus genuine issuance) is an explicit A2.3+ gate.
- F6 (redaction scope, CLARIFIED): ModelError redaction covers
  transport-generated errors/headers/logs; provider content returns
  verbatim as untrusted data. Documented in error.rs; no code change
  (scanning model output would corrupt data and cannot protect a
  credential that never travels in request bytes).
