## 1. Phase 0 — baseline and architecture analysis

Baseline verified before any change: branch `feature/rust-native-core`; A5.4 is its own local commit `d3cfe70`; the tracked tree was clean; the untracked `.aih-e2e-home-*` directories and the three `NEXUS-NATIVE-*.md` specs were never touched.

Dependencies found (reused, not reimplemented):
* **Native tools** (`nexus-tools`): `fs.list/read/search` with typed `deny_unknown_fields` arguments, descriptor-relative `O_NOFOLLOW` walks, special-file/hardlink/mount-crossing/size checks, redaction, sensitive-name policy. Already executed through the daemon verb `tool-execute` = `prepare → Kernel::authorize_tool → begin → execute → finish` with a sealed grant and a witnessed journal.
* **Kernel**: sealed single-use model grants (`published → executed → redeemed`, one dispatch per published intent); `bind_workspace` only for roots committed by the *accepted Controller intent payload* and beneath operator `--workspace-bases`.
* **Controller (JS)**: shadow intents derive `commandId = f(taskInstanceId, attemptId)`.
* **Broker**: issuer identity, `SO_PEERCRED` client identity, closed verb set, run records, recovery, node bridge.

Trust boundaries (A5.5):
```
Client (CLI/Desktop UID) ── text + workspace IDENTITY only ──► broker (issuer UID)
  broker ── Controller bridge (JS) ── Registry-selected exact model ──► sealed Kernel grants (per turn)
  broker ── ONE provider request/turn (Rust HTTPS, credential file) ──► provider  [UNTRUSTED output]
  proposals ──► deterministic validation (fixed catalog, strict args) ──► daemon tool-execute (issuer-authenticated)
     ──► Kernel::authorize_tool (re-checks scope, intent, dispatched turn, workspace binding)
     ──► existing native read tool in the daemon UID ──► bounded, redacted result ──► back to the model
```
The model controls only a tool name and its arguments. It never chooses authority, root, issuer, endpoint, grant or limits.

## 2. The `repo-inspect` intent (versioned, fail-closed)

`NexusIntentV1` (schemaVersion 1) gained `intentType: "repo-inspect"`, `workspaceId` (identity `[A-Za-z0-9._:-]{1,64}`, never a path) and loop limits `maxTurns ≤ 12`, `maxToolCalls ≤ 40`, `maxToolResultBytes ≤ 2 MiB`, `maxRuntimeSecs ≤ 1800` (all can only tighten policy defaults 5 / 10 / 256 KiB / 300 s). `deny_unknown_fields` still rejects `workspace`, `root`, `path`, `tools`, `toolPolicy`, `allowWrite`, `cwd`, `env`, `systemPrompt`, `provider`, `grant`, … Model-only intents may carry neither a workspace nor loop limits, and their payload digest is byte-identical to A5.1–A5.4 (tested). Authenticated client identity, idempotency key, durable task/attempt identity and cancellation are the existing broker mechanisms.

## 3. Workspace authorization and policy

* Operator-configured at broker start: `--workspace ID=ABS_PATH` (+ optional `--workspace-allow ID=UID,…`). Clients list identities with `intent-workspaces`; no verb returns a path. Per-workspace UID allow-lists are enforced at submit and at run start.
* The broker refuses to start if a workspace is `/`, relative, missing, not a directory, **inside or above** a runtime-state directory (broker state, transcripts, ledger, Registry data) or **contains** the issuer capability, credentials, or either socket.
* The Controller intent payload commits to `sha256(canonical root)`; the Kernel's `bind_workspace` refuses any other root and any root outside the daemon's `--workspace-bases`, capturing `(dev, ino)` itself. The daemon must be started with `--enable-repo-inspect --workspace-bases` (forbidden under `production-v1`).
* Confinement is the existing native boundary: symlink components refused, special files/FIFOs/devices/sockets refused, mount crossing and hard links refused, size/binary/UTF-8 checks, bounded output. `.git`, `.ssh`, `.env*`, `*.pem`, `id_rsa*`, `credentials*` etc. were already sensitive; A5.5 adds `.nexus*`, `.ai-harness`, `live-authorization*`, `live-session-authorization*`, `route-verification-authorization*` and `*.cap` (unit-tested, while `authorization.rs` / `capability.rs` stay readable).
* Redaction: native tools redact model-visible output; the broker additionally redacts model-chosen argument text and result previews before they are stored (tested with a credential-shaped search query).
* **Disclosure (not a promise of secret-free source):** any text a tool returns is sent to OpenCode Go. Redaction is pattern-based and incomplete. Select only repositories you accept sending, as the Desktop notice states.

## 4. Model tool declaration and parsing

* `nexus-model/src/repo_tools.rs`: a fixed, versioned catalog — `fs_list`, `fs_read`, `fs_search` (provider function names cannot contain `.`) — with strict JSON schemas (`additionalProperties:false`), arguments identical to the native contract (`startLine`, `maxLines ≤ 400`, `query ≤ 256`, `maxMatches ≤ 50`, …). The OpenCode Go adapter builds `tools` only from this catalog; caller-supplied tools are refused; text-only requests remain tool-free (body keys unchanged, tested). `tool_choice:"auto"`, `parallel_tool_calls:false`, stateless history of `function_call` + `function_call_output` items (the shape the live route probe confirmed for continuation).
* `sse.rs`: `call_id` capture, `response.output_item.added/done`, `function_call_arguments.delta/done`, and `function_call` items inside `response.completed`. Complete provider arguments are authoritative but must equal streamed fragments; `call_id`/name drift, unannounced items, conflicting completions, non-JSON or missing arguments and streams that end before provider completion are **errors, never tool calls**. A response that ends `incomplete` while proposing a tool executes nothing.
* **Not yet confirmed against the real provider:** only a non-streaming `function_call` with a `call_id` has been seen live (A5.4 route verification). The streaming shape is implemented from the Responses specification; the first authorized session confirms or refutes it. A mismatch fails closed.

## 5. Kernel-mediated execution (new authority, narrowly scoped)

New: `SCOPE_REPO_INSPECT` (gated by `Kernel::enable_repo_inspect_pilot`, default off) and `ToolAuthorizationRequest.ai_origin`. For a model-proposed call the Kernel itself requires: pilot enabled; tool scope `read`; provenance well-formed; the command's *sealed* published intent has scope `repo-inspect` and a user-explicit initiator; its provider turn already dispatched (`executed|redeemed`). Existing checks still apply (lease/generation, witness, revocation, cancellation fence, workspace binding digest and `(dev,ino)`, args/budget digests, single-use grant). Journaled `aiInitiated:true` at `authorized` and `completed`. The legacy global dispatch bypass is untouched (`dispatch_enabled() == false`). Daemon `tool-execute` gained only an optional `aiOrigin`. Verified: a write/process/unknown tool, a malformed origin, or a disabled pilot is refused by the Kernel even for an issuer-authenticated caller (tested by calling the daemon directly).

## 6. The loop, bounds, durability and recovery

Each model turn is its own Controller **attempt** of one task (bridge `attempt-add`), with its own command, `publish-inspect` bundle, accept, `workspace-bind`, single-use `dispatch-authorize` grant and request digest — which is exactly "a provider call after a tool result is a new, separately authorized, billable request". Defaults 5 turns, 10 tool calls, 1 concurrent tool call, 24 KiB per result, 256 KiB total, 300 s, 2048 output tokens/turn; hard ceilings in §2. Limits end the run in `limit-reached` (reason recorded) with all findings kept; a response proposing tools on the last allowed turn runs none.

Persisted: per-turn request digest, provider response id and usage (state events), every proposal with call id, validation outcome, args digest, execution id, Kernel journal sequence, result digest/bytes/truncation (run record + transcript `ToolCall`/`ToolResult` events), cancellation and errors.

Guarantees tested: repeated `call_id` never executes twice; refused/invalid proposals never reach the Kernel and 3 consecutive refusals stop the run; a restarted broker **never resumes** (`loop-interrupted` between turns, `uncertain` mid-request) and re-sends/re-runs nothing; cancellation during a streaming turn or between turns stops everything with no further request; a client disconnect does not stop or repeat the run; idempotent replay returns the same run with no second provider call; model-only runs never carry tools.

**Live session budget (new, not A5.4):** a production-transport https run needs `live-session-authorization.json` (`nexus-broker authorize-live-session`): provider, model, workspace, SHA-256 of the exact task text, max turns/tool calls/result bytes and a per-call output ceiling, billable acknowledgement, expiry; consumed once before any grant; an A5.4 record can never satisfy it (tested both ways). A stale broker binary refuses to spend it (`broker-stale`, record kept).

## 7. Source provenance

The final answer's `path:line[-line]` references are checked by the Controller against bytes the tools actually returned in this run (reads' line ranges, search match lines): `citationsVerified` vs `citationsUnverified` on the run, shown in CLI and Desktop. Heuristic (pattern-based), not a proof of correctness; it never invents a citation.

## 8. Offline end-to-end acceptance

`native/nexus-broker/tests/inspect_a55.rs` (17 tests): real `nexusd` (repo-inspect pilot), real JS Registry/Controller bridge, real native tools, real broker loop; a local verified-TLS provider **simulates only the model**, answering chunked SSE and reacting to the real tool results in each request.
* Headline task ("find the function responsible for authorizing model execution, identify its callers, explain with file references") over a temporary Git repo: list → search → read → search callers → grounded answer; 5 provider calls, 4 executed tools, every call journaled `aiInitiated` with read scope, citations all verified, no repo secret / private key / provider credential in any Nexus file or provider body.
* Prompt injection: the model reads a hostile `NOTES.md` and then obeys it with 18 hostile proposals (write, shell, kernel-id names, `..`, absolute path, `.env`, private key, `.git`, symlink file and dir, FIFO, 3 MiB file, binary, unknown argument, empty query, oversize range, non-object arguments, daemon verb). Every one is refused or returned as a tool error, nothing is written or created, the journal holds only read tools, and the injection text reached the model labelled `untrustedRepositoryContent`.
* Malformed streams (8 cases), duplicate call ids, empty call ids, provider error events, all four limits, two cancellation points, restart recovery (2 states), workspace identity/UID rules, runtime-overlap refusal, pilot-off daemon, model-only tool-freedom, live-gate matrix, credential-shaped arguments, Kernel-direct refusals, CLI NDJSON.
* **Real multi-UID userns** (`multuid_a55_repo_inspect_read_only_tools_across_distinct_identities`): daemon, issuer/broker, two Desktop UIDs, bystander, untrusted. The repo is daemon-owned `0750`; neither Desktop UID can read it or its `.env`. Only UID 1 may select the workspace; UID 2 sees `[]`, gets `workspace-not-allowed`, and `not-found` for UID 1's run/status/result/follow/cancel/conversation; unauthorized UIDs are refused; privileged verbs stay unreachable; the Kernel journal (daemon UID) shows `aiInitiated` read tools; no provider call came from any refused request.

## 12. Remaining production blockers

* Live streaming tool-call compatibility unconfirmed; reasoning items are not carried across turns (stateless history) — answer quality under real reasoning models is unmeasured.
* Everything from A5.4 §7 still holds (single-UID dev pilot with `shadow-test` trust, single-process broker, no spend enforcement beyond the operator record, no soak data).
* Repository text leaves the machine for the provider; redaction is heuristic; a hard link to an out-of-workspace file is indistinguishable from an in-workspace file (existing documented tool limit); symlinked *workspace roots* depend on the operator's choice of root.
* Citation checking is syntactic. Desktop polls and was not run against a live broker. A restart abandons an in-flight inspection by design (no resume).
