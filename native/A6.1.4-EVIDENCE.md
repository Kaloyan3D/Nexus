# A6.1.4 — Zero-configuration autonomous engineering harness: evidence

Design: `docs/A6.1.4-DESIGN.md`. Everything is **uncommitted**. Nothing was pushed, merged or deployed. All provider runs are real OpenCode Go (`opencode-go-native` / `muse-spark-1.3-contributor`) on disposable projects under the operator's standing development-test authorization; fixture runs are labelled `fixture` in tests, provider runs `provider` in `docs/acceptance/*.json`.

## What the user does now
Install → connect OpenCode Go once (native key prompt, native consent dialog) → pick a folder with the OS picker → type the request → Run → read the verified report, review the patch, optionally adopt it (native confirmation). No authorization records, env vars, project registration, prompt hashes, daemon or working-copy management, per-edit approvals.

## P0 — `tool-call-incomplete`
Root cause (measured): `max_output_tokens` counts reasoning tokens; at 1024 the provider truncates tool calls (`incomplete:max_output_tokens`). ≥4096 completed 16/16. Fixes: interactive default 16384; truncation is a turn outcome (nothing from it executes; the next turn is a fresh provider request with a doubled cap, ≤2 in a row; then `output-limit`); strict profile keeps the old semantics. No silent retry after an uncertain execution.

## Limits and honest caveats
* Interactive profile is single-OS-user: the automated policy is a boundary of *what* may be done, not separation from a hostile same-user process. Strict profile (independent human approver, multi-UID) is unchanged. production-v1 forbids `--autonomous-workspace-policy`.
* Folder picker and confirmations need `kdialog` or `zenity`. The project registry is unsigned in this profile.
* Supported execution profiles: Rust (cargo), Python (`unittest`/`pytest`/`compileall`, stdlib only), Node (`node --test`, no `node_modules` — projects with dependencies are unsupported). Go and .NET are detected but have no profile (roadmap: need read-only toolchain mounts and cache handling verified in the sandbox).
* Resumption: a crashed/cancelled run is never resumed; a new run reads the current copy state.
* Not done: installer/packaging, Windows, further provider trials on ambiguous/impossible tasks, UI surfacing of context compactions (field exists in the run record).
