## 2. Design (`nexus-tools/src/depcache.rs`)

| Property | Mechanism |
|---|---|
| Content addressing | object id = lockfile sha256 of the `.crate`; `objects/<sha>/crate/<name>-<ver>.crate` + `PROVENANCE.json` |
| Admission gate | sha256(bytes) must equal `Cargo.lock` checksum; strict in-memory archive walk (no links/devices, no absolute/`..`/backslash/NUL paths, single top dir, no case-colliding duplicates, `Cargo.toml` required, file/size/path quotas, decompression ceiling checked before allocation) |
| Atomic, immutable | private `.tmp-*` staging, sealed `0444/0555`, one `rename`; losing racers verify the winner; interrupted staging is invisible and GC'd |
| Index metadata | per-version crates.io index line, admitted only if name/vers/`cksum` match the lock; immutable (hard-link publish, differing content refused) |
| Cache root | absolute, real dir, owner = euid, mode `0700`, `VERSION` = `nexus-depcache/1` or refuse |
| Use-time check | every object re-hashed before each execution; mismatch/symlink/extra file → run refused (`dependency-unavailable`) |
| Sandbox view | per-run `local-registry` (hard links, copy fallback) of **only the snapshot's locked packages**, bound read-only at `/work/vendor`; generated config bound at `/work/out/cargo-home/config.toml`; project `.cargo` is hidden by staging policy |
| Fail closed | missing index entry, unsupported source (git/alt registry), corrupt object, unreadable lock → process never spawned; journal `failed`, `processStarted:false` |

Authority: **no daemon or model operation can populate the cache.** Admission
is an operator CLI (`nexus tools depcache admit --cache <abs> --lockfile
<Cargo.lock> --from-dir <crates> --index-cache <dir>`) run offline from
explicitly supplied artifacts. A networked fetcher was deliberately *not*
added; if wanted it needs separate review and must run outside the sandbox
under a least-privileged identity. The daemon only takes `--dep-cache <dir>`
(read-only use). Cargo itself additionally verifies archives against both the
index and `Cargo.lock` and unpacks to the sandbox tmpfs.

Residual trust: index lines come from an unauthenticated host cache; they are
bound to the lock checksum, and a changed dependency graph makes `--locked`
fail rather than silently resolve. Crates absent from the cache are only an
error if Cargo needs them for the build target (honest cargo failure, offline).

## 3. Real-project acceptance (`native/` in the sandbox, staged snapshot)

| Run | Result |
|---|---|
| admit from host cache | 64 crates + 77 index entries admitted, 13 crates absent, 0 rejected; `verify`: 64 ok / 0 failures; 14 MB |
| `cargo check --workspace --locked --offline` | **exit 0**, ~20 s, `network: none`, `resourceEnforcement: kernel-cgroup`, peak RSS ≈ 1.04 GB, 20 procs; build scripts + proc macros ran sandboxed |
| `cargo test -p nexus-contracts --locked --offline` | exit 0, 7/7 |
| `cargo test --workspace --locked --offline --no-fail-fast` | 343 passed / 92 failed (435 total = host baseline), peak RSS ≈ 1.2 GB |

Cause of the 92 in-sandbox failures (13 targets: nexus-daemon ×11,
nexus-kernel durability/recovery) — **none from cache completeness**:
1. *Filesystem layout:* tests spawn `../target/debug/nexusd` / `nexus-kernel`
   relative to the manifest; the sandbox relocates `CARGO_TARGET_DIR` to
   `/work/out/target` and the env allowlist does not forward `NEXUSD_BIN`.
2. *Synthetic rootfs:* no `/etc/group`, so `parse_socket_group` (`getgrnam`) fails.
3. *Toolchain:* no `node` in the sandbox, so node-driver e2e tests fail.
No project code defect was identified. Those tests remain covered by the host run.

## 5a. Pre-commit cache integrity review (verify → use window)

| Question | Finding |
|---|---|
| Replace/modify an object between verification and sandbox use | The view file the sandbox consumes is now **re-hashed after linking/copying** (`materialize`); a mismatch removes it and fails closed (`cache-corrupt`). Residual: a same-UID writer can still change a hard-linked inode *after* that hash and before bwrap binds it (microseconds); inside the boundary only the Nexus operator UID can do this (see below). |
| Symlink / inode replacement | Archive and index reads use `O_NOFOLLOW`, require a regular file, and are size-bounded; symlinked object or index entry is refused (tests). |
| Hard-link view vs copy fallback | Both paths are hashed post-creation; the sandbox mount is read-only so a run cannot write through the shared inode. |
| Generated index metadata | **Fixed:** index entries were trusted after admission; they are now re-parsed and re-bound to name/version/lockfile `cksum` at every use, single-line, no symlink. |
| Concurrent admission / GC | Admission converges on one object (test, 8 threads). **Fixed:** `gc_staging` could delete a live concurrent admitter's staging dir; it now only removes staging untouched for ≥ 600 s (CLI default). Published objects are never GC'd. |
| Permissions | `0444/0555` and a `0700` root are *hygiene and accident protection only*; the owner can chmod/replace anything. Verification is the control, not mode bits. |

Same-UID tampering with the cache directory remains a **documented
limitation**: an attacker with the operator's UID is outside this trust
boundary (it can equally alter the daemon, kernel keys and the toolchain).
New regression tests: `index_entry_swapped_after_admission_is_refused_at_use`,
`materialized_view_matches_checksum_and_symlinked_object_is_not_followed`,
GC freshness assertion in `interrupted_admission_…`.

Final results after these fixes: depcache host tests 23/23, sandboxed process
tests 5/5, clippy `-D warnings` clean. The heavy in-sandbox workspace test was
not re-run; the earlier figures stand (host workspace re-run after the fixes: **463 passed, 0 failed,
16 ignored**; the 461 figure preceded the two added tests).

## 7. Honest limits

* Multi-UID not run; same production blockers as A3.4 (§12 there).
* Platform-gated crates are index-only; a build for another target will fail
  offline until those crates are admitted.
* Hard-link views need cache and run dir on one filesystem (else copy).
* Index metadata is unauthenticated beyond the checksum binding (§2).
* Cache is single-owner; no multi-user shared cache and no automatic eviction
  (staging GC only).
