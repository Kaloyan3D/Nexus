# A3.1 Evidence — Secure Read/Search Tools

Branch `feature/rust-native-core`, base `96e03de` (A2.5). Nothing committed.

**Scope:** native, deterministic, read-only workspace tools (`fs.list`,
`fs.read`, `fs.search`) bound to Kernel-sealed grants, with a durable,
tamper-evident execution journal, an operator CLI and a typed GUI event
contract.

**Not in scope / unchanged:** write or edit tools, shell/process execution,
live provider dispatch, new daemon IPC. `Kernel::dispatch_enabled()` is still
`false` (pinned by `dispatch_stays_disabled_and_no_write_tool_exists`).

> **Read this distinction first.** Everything below that *executes* a tool
> proves **offline, Kernel-authorized, operator/test-initiated** execution.
> It is **not** AI-driven execution. No model output can reach these tools in
> A3.1: the journal records `aiInitiated: false` on every row, and no daemon,
> model-runtime or GUI path calls the executor.

---

## 1. Architecture

New crate `native/nexus-tools`; additive changes to `nexus-store`,
`nexus-kernel`, `nexus-cli`; types-only change to the desktop GUI.

```
untrusted request JSON ──► prepare()           typed args, budgets clamped, digests,
   (model / renderer)                          workspace identity pinned (stat/open of root only)
                       ──► authorize()         Kernel::authorize_tool → HMAC-sealed grant, journal `authorized`
                       ──► execute()           Kernel::begin_tool_execution (re-verify seal, args/budget
                                               digests, lease, witness, fence; journal `started`, exactly-once)
                                               → descriptor-relative read beneath the pinned root
                                               → Kernel::complete_tool_execution (journal `completed`, redacted)
```

| Layer | File | Role |
|---|---|---|
| Contract | `nexus-tools/src/contract.rs` | `ToolId`, typed `ListArgs/ReadArgs/SearchArgs` (`deny_unknown_fields`), `ToolBudgets` + hard ceilings, `ToolRequestV1`, descriptors |
| Boundary | `workspace.rs` | pinned root, `RelPath` lexical validation, `openat`/`fstatat` walk, policy |
| Tools | `list.rs`, `read.rs`, `search.rs` | bounded, deterministic implementations |
| Orchestration | `authorization.rs`, `exec.rs` | prepare/authorize/execute, `CancellationToken`, `ExecCtx` |
| Results | `result.rs` | `ToolResultV1`, error taxonomy, truncation, deterministic stats |
| Events | `events.rs` | `ToolEventV1` folded from the journal |
| Offline | `offline.rs` | double-gated ephemeral-Kernel harness |
| Authority | `nexus-kernel/src/tools.rs` | `authorize_tool`, `begin_tool_execution`, `complete_tool_execution` |
| Journal | `nexus-store/src/tools.rs` | append-only, hash-chained, HMAC-sealed `tool_journal` |

The executor does not invent authority: it holds no issuance key, cannot
construct `VerifiedToolGrant` (private field, kernel crate), and every
refusal path returns before any workspace content access.

## 2. Tool API contracts (v1)

| Tool | Arguments | Output |
|---|---|---|
| `fs.list` | `path` (default `.`) | `entries[{name,kind,size?,ignored?}]` sorted by raw bytes |
| `fs.read` | `path`, `startLine?` (1-based), `maxLines?` | `content`, `startLine`, `linesReturned`, `eof`, `nextLine` |
| `fs.search` | `query` (1–256 B literal), `path?`, `caseInsensitive?`, `maxMatches?` | `matches[{path,line,text}]` in deterministic traversal order |

`ToolRequestV1` carries: task instance, attempt, command, lease epoch + store
incarnation, request id, cancellation id, tool id/version, args, budgets and
the issuer-supplied workspace root. Results are `ToolResultV1`
(`status ok|truncated|error`, `output`, `error{code,message}`,
`truncation{truncated,reasons}`, `stats`, `outputDigest`, `outputBytes`).
Stats contain no wall-clock values, so results are byte-identical across runs.

Budgets (defaults / hard ceiling): file bytes 1 MiB / 8 MiB, output 64 KiB /
1 MiB, entries 1000 / 10k, per-dir scan 10k / 50k, matches 100 / 1000,
dirs 500 / 5000, files 2000 / 20k, scan bytes 16 MiB / 256 MiB, depth 16 / 32,
line 4 KiB / 16 KiB, deadline 10 s / 60 s. Requests are clamped to the
ceiling; the **clamped** budget digest is what the Kernel seals.

## 3. Filesystem security model

Linux/Unix, `libc`. String canonicalization is **not** the boundary.

* Root opened once (`O_DIRECTORY|O_NOFOLLOW`), `(dev, ino)` pinned and sealed
  in the grant. Root must be absolute, not `/`, not under `/proc /sys /dev`.
* Lexical refusal before any I/O: absolute, `..`, backslash, NUL, control
  chars, `%2e %2f %5c %00` (case-insensitive), leading `~`, over-long/deep.
  `$VAR`/`${…}` are **not expanded** (treated as literal names → `not-found`).
* Each component: `fstatat(AT_SYMLINK_NOFOLLOW)` → classify → `openat(O_NOFOLLOW|O_NONBLOCK|O_NOCTTY)`
  relative to the parent fd → `fstat` and require identical `(dev, ino, type)`.
  Symlinks (any component), FIFOs, sockets, devices are refused; any change
  of device **or mount ID** (incl. same-device bind mounts) is refused, and
  hard-linked regular files are refused (see §8).
* Policy (`WorkspacePolicy`, fixed, not model-tunable, `POLICY_VERSION = 1`):
  * **Sensitive** (refused on read; omitted and counted in list/search):
    `.env*`, `id_rsa*/id_ed25519*/…`, `*.pem *.key *.p12 *.pfx *.jks *.keystore *.kdbx *.ppk *.gpg *.asc`,
    `.netrc .npmrc .pypirc .git-credentials .pgpass`, `credentials*`, `secrets.*`,
    `.git .ssh .gnupg .aws .kube .docker`.
  * **Hidden** (dot-prefixed): refused/omitted, except an allowlist
    (`.gitignore .gitattributes .editorconfig .nvmrc .node-version .prettierrc .rustfmt.toml .env.example .env.sample .env.template .github`).
  * **Ignored dirs** (`node_modules target dist build __pycache__ .venv venv vendor`):
    flagged in listings, skipped by search; directly readable.
* Reads: size check before open of content, `take(max+1)` ceiling during
  read (growth is caught), NUL ⇒ binary refused, invalid UTF-8 ⇒ refused with
  line number, long lines clipped on a char boundary.
* Search: literal substring only (no regex ⇒ no ReDoS), explicit stack
  (no recursion), per-file and global budgets, deadline, cancellation polled.
* Zero writes: files are only ever opened `O_RDONLY`.

## 4. Authorization boundary

A grant (`SealedToolGrant`) is HMAC-sealed under the store's issuance key
(same trust root as dispatch grants, domain `nexus-tool-grant/v1`) and binds:
request id, execution id, command, task, attempt, lease epoch, store
incarnation, tool id/version, **args digest**, **budget digest**, workspace
root digest + dev/ino, cancellation id, issue/expiry (120 s), nonce.

Kernel refuses (`authorize_tool` and again at `begin_tool_execution`) on:
no accepted receipt, task/attempt mismatch, stale lease/incarnation, missing
or rolled-back witness, cancelled (fenced) intent, forged/altered seal,
expired grant, args/budget digest mismatch, duplicate request (`command-conflict`).
The executor additionally refuses a grant that does not describe the prepared
call (workspace identity, ids, cancellation identity) and a token whose id
differs from the sealed cancellation id.

Refused authorizations (before a grant exists) are returned to the caller and
**not** journaled, so forged requests cannot flood the journal.

## 5. Durable records

`tool_journal` (additive table, no schema-version bump): one row per
`(request_id, phase)` with phases `authorized → started → completed`.
Each row stores task/attempt/command linkage, canonical redacted payload,
`prev_hash`, `entry_hash`, HMAC seal. `verify_tool_journal` recomputes the
chain and seals.

Redaction: search queries are stored as length + digest; file/search
content is never stored — only `outputDigest`, `outputBytes`, counters,
truncation, error classification and provenance
(`authority: kernel-sealed-grant`, policy/contract versions, root digest,
`aiInitiated: false`). A `started` row without `completed` is a crashed or
in-flight execution and is never automatically re-run (`interrupted` in the
event view).

## 6. CLI / GUI

CLI (`nexus tools …`), no daemon contact and no issuer capability:

* `tools list`, `tools inspect <id>` — static contract metadata.
* `tools run-offline --offline-test --workspace <dir> <id> '<json>'` —
  requires **both** the flag and `NEXUS_TOOLS_OFFLINE_TEST=1`. Builds a
  throwaway Kernel in a private temp dir (deleted afterwards), runs the real
  prepare→authorize→execute path, and labels output
  `controllerAuthorized:false, aiInitiated:false`. It shares nothing with the
  daemon store, so it confers no authority over any real task.

GUI: typed `ToolEventV1` contract (Rust `events.rs`, mirrored in
`src/lib/contracts.ts`) plus a pure presentation mapper
(`src/lib/toolEvents.ts`). **No Tauri command, capability, daemon IPC or fs
permission was added**; React cannot execute tools. Wiring events into
Conversation/Activity/Tool details/Verification needs a read-only daemon op
(A3.2 prerequisite below). No assistant messages are ever derived from tool
records.

## 8. Final security audit (post-implementation)

### 8.1 Findings and fixes

| # | Finding | Severity | Fix | Regression test |
|---|---|---|---|---|
| F1 | **Same-device bind mounts were not detected.** `st_dev` is identical for a bind mount of the same filesystem, so `ws/d` bind-mounted from outside the workspace was readable. | High | Every entry is `statx`ed (`STATX_MNT_ID`) and must match the root's mount ID; root refused if the kernel cannot report mount IDs. Additionally each component is opened with `openat2(RESOLVE_NO_XDEV\|NO_SYMLINKS\|NO_MAGICLINKS\|BENEATH)` so the kernel enforces it too (fallback to `openat(O_NOFOLLOW)` + userspace checks on `ENOSYS`/`EPERM`). | `same_device_bind_mount_is_refused` (real `unshare -rm` + `mount --bind`; asserts `st_dev` equal, result `mount-crossing`) |
| F2 | **Hard links to out-of-workspace files were readable** (indistinguishable from local files). | Medium | Regular files with `nlink > 1` are refused (`hardlink-refused`), except beneath conventional dependency/build dirs (`node_modules`, `target`, …) where hard-linking is normal. Search counts `skippedHardlinks`. | `hard_links_to_outside_files_are_refused` |
| F3 | **Secrets inside permitted files were returned verbatim**, and `fs.search` could act as a prefix oracle. | Medium | Bounded line-oriented redaction (`redact.rs`) applied before clipping/returning; search matches the *redacted* text; results carry an explicit `redaction{redacted,count,kinds}` marker; journal stores only kinds/counts. | `secrets_in_permitted_files_are_redacted_and_marked`, `redact::tests` |
| F4 | **Tail truncation of the journal was undetectable.** | Medium | Journal tail `(count, hash)` is sealed and checkpointed into the independent witness DB after every append; `verify_tool_journal` fails if the store is shorter than, or diverges from, the checkpoint. | `tail_truncation_is_detected_with_witness_checkpoint_only`, `checkpoint_tolerates_…` |
| F5 | Root on a pseudo-filesystem (procfs, sysfs, cgroup, devpts, debugfs, tracefs, bpf, nsfs, pstore, selinux…) reached via a path that does not start with `/proc` etc. | Low | `fstatfs` magic check on the root. | covered by root-refusal tests for prefixes; magic check exercised only structurally (no non-root way to mount procfs elsewhere in tests) |

All fixes were verified by mutation: disabling the mount-ID/`NO_XDEV`
checks and the hard-link check makes the bind-mount and hard-link tests fail.
The earlier symlink mutation check also still fails 3 tests.

Reviewed and found sound (no change): pinned `(dev, ino)` + post-open
identity comparison; `O_NONBLOCK|O_NOCTTY` opens (FIFO cannot block);
symlink/rename races (both swap-race tests, 30k iterations each);
`..` and absolute paths (lexical + descriptor-relative); special files;
cancellation polled per directory, per file and every 512 lines.

### 8.2 `openat2` / mount-ID evaluation

`openat2` with `RESOLVE_BENEATH|NO_SYMLINKS|NO_MAGICLINKS|NO_XDEV` is
strictly stronger than the userspace walk for a single resolution because
the kernel performs it atomically; it is now used per component with the
userspace `fstatat`→`openat`→`fstat` identity and mount-ID checks retained
(they also give typed errors and work when `openat2` is unavailable).
`st_dev` alone is **not** treated as proof of isolation. The tools require
Linux ≥ 5.8 (`STATX_MNT_ID`); older kernels are *refused*, not degraded.

### 8.3 Output boundaries

| Boundary | Content | Protection |
|---|---|---|
| Raw authorized output | file bytes under path policy | never leaves the executor unredacted |
| Model-visible output | `ToolResultV1.output` | redacted; `redaction` marker; `outputDigest` is of the redacted text |
| Persisted record | `tool_journal` payload | digests, counters, redaction kinds/counts; no content, no query text |
| UI diagnostics | `error.message`, `ToolEventV1` | fixed strings; no file content or host paths (tested) |

Redaction covers: PEM private-key blocks (multi-line, correct across
`startLine` paging), `sk-`/`ghp_`/`gho_`/`ghs_`/`github_pat_`/`glpat-`/`xox*-`/
`AKIA`/`ASIA`/`AIza`/`npm_` tokens, JWTs, `Bearer` tokens, and
`password|secret|token|api_key|…` = value assignments with non-placeholder
values. **Limitations:** pattern based; it will miss unlabelled or
high-entropy secrets, secrets split across lines (other than PEM), encoded
or concatenated secrets, and secrets in non-text formats; it may redact
benign values with secret-like names. It is a conservative backstop, not a
guarantee, and cannot be disabled by the caller.

### 8.4 Grant exactly-once: durability scope

* Single use is enforced by `UNIQUE(request_id, phase)` in the Kernel SQLite
  store (`WAL`, `synchronous=FULL`) inside an `IMMEDIATE` transaction, under
  the cross-process kernel file lock. It is therefore **durable and
  cross-process**, not process-local. Verified with 6 separate OS processes
  racing one grant (exactly 1 winner), 8 kernels × 5 executions, and restart
  before/after `begin`.
* A `started` row with no `completed` (crash) is never re-executed; it
  surfaces as `interrupted`.
* Scope limit: exactly-once covers *authorization to read*, not the side
  effects of the read (there are none). The Kernel fence (cancelled intent)
  and lease are checked at `authorize` and `begin`; **mid-execution** fencing
  is observed only through the in-process `CancellationToken`, not by
  re-polling the Kernel.
* Grants expire after 120 s; unexecuted `authorized` rows are not reaped.

### 8.5 Journal integrity guarantees

Detected by `verify_tool_journal`: edited payload/linkage, forged insertion,
reordering, mid-chain deletion, replayed `(request, phase)` (rejected at
append), forged checkpoint (bad seal). Uncommitted partial writes are
invisible (SQLite transaction). **Tail truncation is detected only when a
witness is configured and only back past the last checkpoint**: a crash
between append and checkpoint leaves the store at most one entry ahead of
the checkpoint (tolerated by design), so the newest un-checkpointed entry can
be removed undetected. The witness is a separate SQLite file under the same
OS user; an attacker with write access to both files and the issuance key can
rewrite both. This is an *independent checkpoint*, not external anchoring,
and is **not** claimed as full truncation resistance. Without a witness
(`Kernel::open(db, None)`) tail truncation is not detectable (tested).

## 9. Limitations

* **Linux ≥ 5.8 only** (`statx` mount IDs, `openat2`); other platforms and
  older kernels are refused or unsupported, not degraded.
* **Bind/same-device mounts and mount points are refused**, including
  legitimate ones inside a workspace.
* **Hard links outside dependency/build directories are refused**; a hard
  link inside `node_modules`/`target`/`vendor`/… to an out-of-workspace file
  is *not* distinguishable and is permitted by that exemption.
* **No `.gitignore` parsing**; "ignored" is a fixed directory-name set.
* **Redaction is best-effort** (see §8.3).
* **Tail truncation**: see §8.5.
* The workspace root string is issuer-supplied (trusted); ancestor symlinks
  are resolved by canonicalization before pinning.
* Deadline truncation is wall-clock based and not deterministic under load.
* No daemon/IPC surface exposes tools or events, so the GUI contract is not
  fed by live data.
* `run-offline` removes its own scratch dir (`remove_dir_all` on a private
  random temp path); it is the only deletion in the crate and never touches
  the workspace.

## 11. Prerequisites for native daemon tool integration and A3.2

1. Reviewed daemon IPC op for tool execution + read-only `tool_events`
   query (the approved path for GUI/CLI), authenticated like existing ops.
2. A Controller-published, Kernel-sealed **workspace binding** per task
   (today the root is passed by the issuer at request time).
3. Write-intent grants: separate tool ids, pre-image digest binding,
   atomic temp-file + `renameat` into the pinned directory fd, size/path
   policy, and journal phases that distinguish *planned / applied / verified*.
4. Rollback/undo story and conflict detection (pre-image hash compare).
5. Decide whether pattern redaction is sufficient or output needs a policy/allowlist layer.
6. External anchoring of the journal checkpoint (current witness is same-host/same-user).
7. Mid-execution Kernel fence polling.
7. Wire AI-initiated calls only after the above; A3.1 deliberately has none.
