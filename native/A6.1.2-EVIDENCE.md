## Gaps for a real project workflow (audit)
1. **Onboarding.** One git source per instance, set by env var (`A56_CODE_SOURCE=ID=PATH`) before `start`, with a manual commit pin and write scope. No operator command to list, register, re-pin or remove projects; changing project means restarting the instance. Desktop correctly cannot register, so an operator-side path is the missing piece.
2. **Workspace lifecycle.** Working copies live under `<base>/worktrees/` with no Desktop-visible discard/retention/size, no "refresh to new commit" (the daemon refuses any HEAD other than the pin), and the source must be clean. No patch export from the Desktop (diff is view-only).
3. **Build/test commands.** Allowlist is `cargo` (check/test/build/fmt), `npm` (test / run build), `tsc --noEmit`, in a network-off sandbox. Rust-centric: no pytest, go, make, gradle, dotnet; JS projects need an offline `node_modules`; cargo needs the admitted dependency cache.
4. **Multi-step usability.** Fixed limits (12 turns, 30 tool calls, 5 edits, 5 commands, 30 min) are not user-adjustable; approvals expire (default TTL) and need a separate approver terminal per operation, which makes multi-file tasks slow; reads cannot be scoped; no "continue / retry from this state" after a limit or expiry; test output is bounded.
5. **Unverified in a live setting:** reconnect/persisted history with real OpenCode Go, and behaviour on a real multi-file project.

## Proposed small plan (each step needs its own review; none widens tool permissions)
1. `nexus-broker` operator subcommands `project add|list|remove` writing a signed/owner-only projects file (path, commit pin, write scope) read at start; Desktop stays read-only.
2. Daemon/broker `worktree list|remove` + a read-only Desktop "copy: path, size, age" line; operator-only discard.
3. Read-only patch export (`nexus intent diff` already exists) as a Desktop "Copy patch" button.
4. Let the operator raise nothing; allow *lowering* per-run limits and surface approval TTL in the composer.
5. Independent non-Nexus project rehearsal offline (scripted model), then request fresh live authorization for the final acceptance.
Extra language runners (pytest, go) only after a separate security review.
