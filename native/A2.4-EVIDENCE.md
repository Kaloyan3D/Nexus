## 1. Client API architecture (nexus-client v1)

One authoritative, versioned surface (CLIENT_API_VERSION = 1, IPC_PROTOCOL_VERSION = 1)
shared by the CLI and the future GUI. Crate `nexus-client` exposes: status, health,
readiness, receipt, journal, digest (all read-only daemon IPC); tasks/task_show (read-only
Controller ledger JSON); attempt_status; models (offline mock catalog + live blockers);
verify (receipt + journal + digest bundle); cancel (gated: always `unauthorized` for normal
users); poll_journal streaming; run_mock (isolated mock workflow); live_blockers.
No operation opens SQLite; kernel state arrives only through the authenticated IPC boundary.
No raw issuer capabilities or provider credentials cross to CLI users; all errors redacted.

Ten architecture questions:
1. Source of truth: daemon Kernel/store owns grants/receipts/journal; Controller ledger files
   own task definitions; Registry JS service stays the only live model authority (client only
   reports an offline mock catalog). Every client read is derived and re-derivable.
2. Ownership: only the daemon mutates kernel state via privileged IPC with issuer-HMAC auth.
   The client mutates nothing except its isolated throwaway mock store. CLI/GUI are consumers.
3. Dependency direction: nexus-cli -> nexus-client -> daemon IPC/kernel views; nexus-model
   -> nexus-kernel for grant verification (acyclic: kernel never depends on model). No cycles.
4. Service boundaries: Unix-socket JSON frames (protocol v1, exact keys) plus typed Rust
   functions. Forbidden to cross: issuance keys, credential values, SQLite handles, daemon
   capability keys, shell/filesystem vocabulary.
5. Failure semantics: daemon down -> `disconnected` (exit 3), no synthesized terminal;
   slow -> 10 s IPC timeout; garbage -> typed refusal. Streaming stops on cancel token;
   attempts stay non-terminal and are never re-sent.
6. State lifecycle: per-command short-lived IPC connections; journal polling for streams;
   mock workflow owns a tempdir Kernel destroyed on return; CLI never disposes daemon state.
7. Test seams: MockTransport scripts all wire behavior; TempDir kernels per test; no sleeps;
   client tests assert version/redaction/blocked/mock determinism without a daemon.
8. Migration/compatibility: sealed-grant IPC fields are additive (old readers ignore extras);
   plain-grant kernel path preserved; rollback = previous client binary, no data migration.
9. Observability: `status`/`doctor`/`readiness`/`journal`/`digest` answer 'is it working' from
   outside; CLI exit codes are deterministic (0/1/2/3/4/5/6).
10. Security: new inputs are socket paths/ledger dirs/prompts (validated, redacted); new
    outputs carry no secrets; privilege boundary = daemon issuer-HMAC + UID allowlist + socket
    perms, all preserved (A2.1 policy untouched). Mock credentials are test markers only.

A2.1 socket permissions are NOT relaxed: owner-only DataRoot rule unchanged, group sharing only
via the existing explicit --socket-group path. No raw issuer capability is handed to CLI users:
`cancel` returns `unauthorized` with guidance instead of accepting a capability argument.

## 2. Authorization and grant design (closes the A2.3 transport gap)

A2.3 audit finding 9: `Transport::send` was publicly callable on any attested request without
independently verifying Kernel authorization. A2.4 establishes a genuine authority boundary:

- Sealed grant token: `Kernel::authorize_sealed_dispatch` consumes the published intent
  (exactly-once, same nine revalidation checks as A2.3) and mints
  `SealedNativeDispatchGrant` binding command, attempt, task, request digest, endpoint origin,
  scope, target digest, extension digest, lease epoch, store incarnation, credential ref,
  issued_at_ms, expires_at_ms (issued + 300 s TTL), nonce, granted_at_utc, plus
  tag_hex = HMAC(issuance_key, canonical(grant) under domain `nexus-dispatch-grant/v1`).
  Only the kernel holding the sealed issuance key can mint it; CLI/GUI cannot forge, extend,
  or refresh one (proven by `self_issued_grant_without_kernel_key_is_refused`).
- Verification immediately before transmission: `nexus-model::authorized::dispatch_authorized`
  takes `&mut Kernel` as the trusted in-process handle, calls
  `Kernel::verify_sealed_grant` synchronously in the same function with no yield before
  `transport.send`, then sends at most once. Raw `Transport::send` remains as a documented
  low-level test primitive but is unreachable through the production API, which requires the
  kernel handle plus the sealed grant.
- Verify re-checks: scope == mock-e2e; field completeness; expected request/endpoint/credential
  binding; expiry (ReservationExpired) and issued-at skew/future; TTL tamper (ForgedIssuer);
  tag HMAC; intent row exists and is `executed` (published => forged, cancelled => fenced);
  intent seal; bundle-vs-grant agreement; extension origin/credential agreement + loopback;
  receipt agreement; lease currency (StaleLease); witness health/rollback.
- Replay/duplicate: intent `executed` makes second authorize `command-conflict` (pinned for both
  plain and sealed paths, incl. an 8-thread sealed race granting exactly once). At the network
  layer AttemptTracker::require_not_sent plus AttemptStore::preflight refuse replays without new
  bytes; a completed authorized send records grant-consumption (`AttemptOutcome::Sent`) so a
  re-presented grant with dropped attempt state still sends nothing; uncertain outcomes record
  `uncertain` (never retried). Proven by `second_authorize_after_sealed_is_conflict`,
  `concurrent_sealed_authorize_grants_exactly_once`, `replay_after_success_sends_nothing_more`, and
  `replay_with_fresh_tracker_after_success_sends_nothing_more` (the last caught a real second-send
  hole during the final audit; fixed, see section 5b finding F1).
- Cancelled/revoked: fence-before-authorize refuses at authorize; credential revoke refuses at
  `credential.check` before any byte; generation advance refuses as stale lease. Post-authorize
  fence races resolve exactly-once by store transition (published->executed vs published->
  cancelled): exactly one winner, the other fails closed. No alternate authorization path was
  created: the plain-grant path shares the same checks and consumption; dispatch_enabled stays
  false and authorize_dispatch still always refuses.
- Daemon: `dispatch-authorize` now returns the full sealed grant (additive fields; old readers
  ignore extras). All A2.3 durability/fencing behavior preserved (9/9 E2E still green).

## 2b. Actual transport authority boundary (final-audit determination)

A description of `Transport::send` as test-only is not, by itself, a boundary: any in-process
Rust caller can invoke the public trait. The real boundary is layered and was verified in code,
not comments:

- Process isolation: the issuance key, sealed store, and grant minting live in the daemon
  process. CLI/GUI processes never hold the key, the store handle, or a `&mut Kernel`; they
  cannot mint, verify, or refresh grants. `dispatch_authorized` requires the kernel handle, so
  out-of-process callers have no path from grant JSON to network bytes.
- Credential ownership: `Credential::test_credential` is the ONLY credential constructor in the
  tree (no env/file/loader exists; live issuance is an unbuilt explicitly-listed blocker). No
  live credential can exist, so no direct `send` call can be billable or carry real secrets.
- Endpoint confinement (mechanical, pinned by tests): `HttpSseTransport::send` refuses `https`
  pre-connect (no TLS stack; plaintext-to-TLS-port would leak); `target.rs` refuses non-loopback
  `http` and non-loopback `localLoopback` claims. The only reachable network is loopback test
  doubles with test markers.
- Scope confinement: the kernel authorizes exactly `mock-e2e`; live scopes are refused by name at
  publish, authorize, and verify; `dispatch_enabled()` is false and `authorize_dispatch` refuses.
- Grant consumption (this audit): mint-once is durable (intent `executed`, second authorize is
  `command-conflict` under an 8-thread race pin); send-once per store is now recorded
  (`AttemptOutcome::Sent`; finding F1 below).
- Residuals (accepted, unchanged from A2.3 shape, narrower window): microsecond verify-to-connect
  lease TOCTOU across processes (same-function CPU-only gap; A2.3's authorize-to-dispatch window
  was wider); cross-process re-presentation of a copied grant JSON (mint stays once; per-grant
  durable send-ledger would need a consumed-nonce table, flagged for the broker milestone, not
  built here); same-UID adversaries per A2.1 scope.

## 4. Interactive terminal interface

`nexus interactive` is a line-based session kept separate from execution logic (it only calls
`nexus-client::run_mock` and `api::probe_daemon`; the Controller state machine is never
duplicated). Per turn it shows: the mock terminal text, wire-order stream events ([stream i]),
attempt/command/digest binding, finish reason + usage, and a verify line binding the terminal to
the attempt. Model/reasoning banner on entry (`e2e-mock-model [mock-e2e, loopback] | low`) with
`/model` to re-show; `/status` probes the daemon; `/quit` exits; mock vs live is explicit on
every turn (`[mock:running]`/`[mock:done]`, live BLOCKED banner). Cancellation: Ctrl-C / EOF ends
the session; per-turn cancel token support is wired through dispatch_authorized (proven by
`cancelled_token_sends_nothing`). A full ratatui-style TUI was deliberately deferred: no new
terminal dependency was justified for A2.4, and the line protocol already exercises the shared
streaming event semantics the GUI will reuse.

## 5. Security findings and fixes

- [FIXED] Public transport bypass (A2.3 finding 9): raw `Transport::send` accepted any attested
  request. Fixed by sealed grants + `dispatch_authorized` verify-before-send + kernel-handle
  authority. Failing-first tests: 12 kernel sealed-grant tests + 7 model authorized tests, all
  asserting zero provider sends on refusal (MockTransport sends == 0).
- [FIXED] Grant forgery/self-issuance: HMAC tag under the sealed issuance key; foreign-key grants
  refused as forged-issuer; TTL tamper refused as forged-issuer.
- [FIXED] Replay/double-billing: exactly-once intent consumption + tracker/store duplicate
  suppression; second authorize is command-conflict; replayed network dispatch sends nothing.
- [FIXED] Stale/cancelled/revoked: expiry TTL, stale-lease on generation advance, revoked
  credential and cancelled token send nothing; fence-before-authorize refuses.
- [CHECKED] Secret exposure: credential values never enter kernel/store/snapshots/errors/logs
  (refs only); CLI `config show`/`models` carry paths and refs only; redaction unit tests pin
  every error path; MockTransport secret tripwire stays 0. Daemon capabilities never given to
  CLI users (`cancel` is unauthorized-by-design for normal users).
- [PRESERVED] A2.1 socket/DataRoot permissions, UID allowlist + issuer-HMAC gates, A2.3 seals,
  fencing terminality, witness checks, dispatch_enabled == false. No new trust mechanism was
  added; the sealed-grant tag reuses the existing issuance-key trust root under a new domain.
- No open security findings remain in the mock scope. Same-UID fabrication stays out of scope per
  A2.1 (file-ledger forgery alone authorizes nothing without the daemon capability key; a
  same-UID peer holding the key is indistinguishable by design).

## 5b. Final-audit findings (confirmed, fixed, verified)

- [F1 FIXED] Grant replay after success with dropped attempt state caused a SECOND provider send.
  Reproduction (failing-first `replay_with_fresh_tracker_after_success_sends_nothing_more`): same
  sealed grant + fresh `AttemptTracker` + same `AttemptStore` returned `Ok` with `bytes_sent=true`
  (sends 1 -> 2), because success recorded nothing and preflight stayed `Fresh`. Root cause: the
  authorized layer consumed the kernel intent at authorize time but never recorded network
  consumption, so only the caller's tracker (droppable) stood between a replayed grant and the
  wire. Fix (minimal, no schema change): new `AttemptOutcome::Sent` + `record_sent` on every
  successful authorized send; preflight refuses same-or-different bytes for a sent attempt with
  `duplicate-attempt` and zero new bytes. Verified: 7/7 authorized_dispatch green, full workspace
  226/0/9. Residual: cross-process re-presentation of copied grant JSON (store is per-process;
  mint stays durable-once; per-grant durable send-ledger deferred to the broker milestone).
- [F2 FIXED] CLI `status`/`doctor` rendered `?`/`UNKNOWN` against a REAL daemon: they read `version`/
  `lifecycle` and top-level `verdict`, which the daemon never sends (it sends `state`/`trustMode`/
  counts and nests the report under `readiness`). Found by a live round-trip against a temp
  `nexusd` (readonly, owner-only socket `srwx------`); fixed to the real keys and re-verified live:
  `nexus daemon: ready (trust readonly, commands 0/0, events 0)`, `readiness: NOT_READY`. Regression
  cover: CLI tests pin JSON shapes; live-shape drift remains a standing risk until a daemon-backed
  CLI test exists (flagged for A2.5 harness, not added here to keep the suite daemon-free).
- [F3 FIXED] `authorized.rs` docs overstated the store as `durable` and replays as returning the
  `committed terminal`; the store is per-process memory and replays refuse with `duplicate-attempt`.
  Corrected in place; no behavior change.
- [CHECKED] No broker required in A2.4 (permission model verified live, see 5c): read-only daemon
  commands take no issuer auth (server `dispatch()` skips `authorize()` for them; CLI sends no auth
  frames); privileged commands refuse without it (`privileged-disabled` probed live over the real
  socket); socket transport is owner-only by default (`srwx------`, umask 077, DataRoot 0700
  enforced with fatal refusal on 755 dirs, observed); absent/EACCES sockets map to honest exit-3
  `disconnected`. A world-readable broker would newly expose receipts/digests/task IDs to all local
  users, so it is NOT built; per-user daemons (the default layout) plus the existing explicit
  `--socket-group` path cover owner and shared deployments, and Tauri (same-UID) reuses them.

  CLI tests pin that ledger output never contains `cmd-mock-1` and mock output always contains
  `[mock]`, so a synthetic task can never be mistaken for a Controller task.
- Blocked pending live authorization: bare `run` -> BLOCKED panel + exit 5, zero network I/O.

Command capability matrix: real state = status/doctor (+readiness/receipt/journal/digest via API

## 8. A2.5 GUI integration contract

The future React + TypeScript GUI (possibly Tauri v2) must consume the same `nexus-client` v1
surface, never CLI stdout parsing. Recommended adapter: Tauri commands (or a localhost
authenticated bridge) calling, 1:1: status/health/readiness/receipt/journal/digest,
tasks/task_show/attempt_status, models, verify, poll_journal (ordered ClientEvents with seq/kind),
cancel (surfacing `unauthorized` honestly), run_mock (isolated; returns MockRunReport),
live_blockers (render the BLOCKED panel). Event semantics: journal order = durable store order;
SSE order = wire order; cancellation is cooperative and non-terminal; disconnects surface as
`disconnected`, never synthesized terminals. Permissions: GUI gets the same read-only surface as
the CLI; privileged mutations require the operator-held daemon capability, which is never
embedded in the GUI bundle. Versioning: CLIENT_API_VERSION bumps only on breaking contract
change; additive fields (as in this milestone) keep old readers working. No GUI is built in A2.4.
