## 1. Phase 0 — what `dispatch_enabled() == false` actually protects

Read-through of kernel `lib.rs`/`dispatch.rs`, A2.2–A2.5, A4.4, daemon `server.rs`, client `mock.rs`/`conversation.rs`:

* `Kernel::dispatch_enabled()` is a constant `false`; `Kernel::authorize_dispatch()` is a function that always returns
  `DispatchDisabled`. They guard the **legacy, general "this command may produce effects" authority** and are what status,
  readiness and the production profile report. Neither is consulted by the sealed-grant path.
* Model transmission authority is a **separate, narrowly scoped capability**: a kernel-HMAC-sealed `SealedNativeDispatchGrant`
  bound to one request digest, one attempt, one endpoint origin, one credential reference, one scope, TTL 300 s. Before A5.1 the only
  admitted scope was `mock-e2e` (loopback). That path never confers tool, file, process or approval authority: those are separate
  daemon commands (`tool-execute`, `approval-*`) with their own sealed bindings and gates.
* Therefore model-only inference **can be separated from disabled tool dispatch without touching the guard**. No stop-and-propose was
  needed; the guard was left byte-for-byte as it was.

Two facts found during Phase 0 that shaped the design:

1. The daemon crate has no model code, no network and (in `deploy/nexusd.service`) `RestrictAddressFamilies=AF_UNIX`. Putting an
   HTTP client + provider credential into the privileged daemon would have widened its trust surface and contradicted the A4.4
   unit. **The network and the credential therefore live outside the daemon**, in the issuer-identity Controller-side executor.
2. A2.4 verified a grant only with an in-process `&mut Kernel`, which an out-of-process sender does not have, and recorded
   "per-grant durable send-ledger … flagged for the broker milestone" as an accepted residual. A5.1 closes that residual with a
   daemon-side durable **redemption** (§3).

The Controller authority chain is unchanged and still mandatory: Registry issuance → sealed extension → Controller intent
(bound to the exact request digest) → accepted receipt on a live lease → sealed grant. `nexus-client::model_run` mints nothing and
holds no issuance key; it can only *redeem* what the daemon minted.

## 3. Model selection and routing guarantees

* **Registry is the only authority.** The extension (endpoint, billing, model id, credential reference, limits) is Registry-issued and
  kernel-sealed by digest; the Rust target is rebuilt from it and cross-checked against the sealed core (`wrong-target` on drift).
* **Expected target.** `ModelRunRequest.expected {providerId, remoteModelId}` — when given, a mismatch is `wrong-model` *before* any
  state, credential read, or network I/O (`a51_wrong_or_unavailable_model_is_rejected_before_any_billable_step`: zero provider
  connections, zero transcript). Different provider → refused; different model → refused; tampered extension → refused.
* **No fallback, no upgrade, no second provider.** There is no code path that selects a different target; routing policy is
  untouched (the JS Registry was not modified apart from the intent scope). One provider/one model per attempt, bound by the
  kernel to `targetDigest` + `extensionDigest` + `requestDigest`.
* **Configuration validated before anything billable.** Target validation, endpoint policy and the protected credential file are all
  checked before `model-redeem`; a bad credential file does **not** consume the grant (`…credential_never_leaves…` re-uses the
  same grant after fixing the file).
* **Provenance** (`ModelRunStatus`, also `model-state-*` transcript events): provider id, remote model id, logical Registry target,
  endpoint kind (`provider` vs `loopback-test-double`, derived from the origin, never asserted), attempt id, command id, request digest,
  HTTP status, usage, latency, finish reason, error code.

## 4. Provider credential protection

* Source: a **protected backend file** `{ "<credentialRef>": "<token>" }` loaded by `Credential::from_protected_file`:
  `O_NOFOLLOW`, regular file, owned by the euid, **no group/other bits**, `nlink == 1`, ≤ 64 KiB, printable ASCII token (no
  whitespace/CRLF). Every refusal is redacted (tested: file contents/token never in errors).
* The credential reference is the sealed extension's `credentialRef`; the file is selected by the *operator* (`--credentials`), not
  by the model, the GUI, or IPC.
* Where the secret appears: one `authorization` header on the socket. Verified absent from: request body, IPC frames/responses,
  kernel store + witness files, transcript files, `status`/`journal` responses, daemon stdout/stderr, `ModelRunStatus` JSON, CLI
  output (`a51_provider_credential_never_leaves_the_protected_file_and_wire_header` scans bytes on disk and daemon logs).
* The daemon never sees the token. The Tauri backend references no executor/credential symbol (source-pinned test) and its
  status DTO is an exact credential-free field set (pinned test). The renderer has no API that can return one.

## 6. Task / attempt durability semantics

Durable lifecycle (append-only, hash-chained, fsynced transcript; `model-state-*` events):
`accepted → target-selected → authorized → request-started → streaming → {completed | cancelled | timed-out | provider-failed |
uncertain | refused | failed}`.

* **Write-ahead.** `request-started` is persisted *after* redemption succeeded and *before* the first request byte is written.
* **Exactly-once across processes and restarts.** Kernel intent: `published → executed` (mint) `→ redeemed` (redeem). A second redeem,
  re-authorize, or re-presented grant is `command-conflict`, including after daemon restart
  (`redemption_is_durable_and_single_use`, `a51_executor_death_and_daemon_restart_during_inference_stay_uncertain`).
* **Uncertain submission.** Send failure after bytes may have left, silent close, timeout after send, stream cut → `uncertain` /
  `timed-out`; the attempt is never re-sent and the grant cannot be redeemed again.
* **Crash/restart.** The executor SIGKILLed mid-stream *and* the daemon restarted: transcript has `request-started`/`streaming`
  without a terminal; `recover_model_run` appends an explicit `uncertain` (`send-uncertain`); the restarted daemon refuses the grant;
  provider connections = 1. A run that died before `request-started` is closed as `refused` (nothing sent).
* **Provider vs local vs fixture.** `Source::NativeStore` + `endpointKind`; locally generated errors are `Speaker::Runtime`/`System`
  with `error_code`; loopback doubles are labelled "not a real provider" in the status text and the UI.
* **Honest limits.** Receipts and the model-attempt transcript are *not* witnessed (A4.4 blocker 5 still applies); the transcript is a
  local hash chain (no external anchor). Concurrent distinct attempts for one task are not specially serialized here.

## 7. Model-only security boundary

The model path can return **text only**; everything else is structurally absent:

| Forbidden capability | Why it is unreachable | Evidence |
|---|---|---|
| Tool execution / file read-write / shell / sandbox | the executor references none of `tool-execute`, `workspace-bind`, `std::process`, `nexus_tools`; request bytes carry no tool definitions; tool-call fragments are dropped | `executor_has_no_tool_process_filesystem_or_authority_surface` (source pin), `a51_model_generated_tool_instructions_remain_inert_text` (no tool record/event, no file created, `tool-execute` refused) |
| Mint Kernel grants / issue approvals | no key, no IPC command named; `model-redeem` only consumes | source pin; `redeem_sealed_grant` cannot mint |
| Modify Registry / daemon flags | none of that surface exists in client or GUI | Tauri allowlist tests |
| Second provider | one target per grant, digest-bound | kernel binding tests |
| Trusted-command interpretation | assistant text is stored as `ModelGenerated` text; rendered by `MarkdownLite` (no links, no HTML) | desktop `renders hostile model output as inert text` |
| Background/autonomous use | pilot flag default off; intent must carry `initiator: user-explicit`; the executor is a one-shot CLI invocation, no loop/daemon mode | `explicit_user_initiator_is_required`, JS `NativeDispatchIntent` tests, `a51_pilot_is_disabled_by_default…` |

Separate gating (three independent locks): daemon `--enable-model-pilot` (needs shadow-test + `--allowed-uids`; refuses to start
otherwise — `a51_pilot_flag_requires_peer_uid_gate_and_shadow_mode`), a user-explicit initiator sealed into the published intent,
and an explicit operator CLI invocation with a Controller-minted grant.

## 8. Nexus Desktop

* Reused the existing `ConversationPanel` / `useConversation` live-follow (cursor polling) — no second chat component.
* New: model runs in the task list (provider/model, endpoint kind, state), a heading and **Activity** panel with provider/model/
  endpoint/attempt/command/digest/HTTP status/usage/latency/finish, uncertainty and error alerts, and a **Cancel run** button.
* Output is untrusted text: `MarkdownLite` emits only text nodes (no HTML, no links); test injects `<script>`, `<img onerror>`,
  `javascript:` links, `<iframe>` and asserts none become elements.
* Tauri: 3 new commands — `list_model_conversations`, `model_run_status` (read-only) and `cancel_model_run` (writes a stop marker;
  cannot start/resend/authorize). Capability file adds exactly those three `allow-*`; no fs/shell/http/opener plugins; allowlist,
  build manifest and capability tests agree; CSP unchanged.
* **Deliberate omission: GUI-initiated submission.** Starting a run requires the issuer capability and a Controller-minted grant.
  Giving the Tauri backend either would hand the desktop session issuer authority (and the provider credential), which A4.x
  explicitly keeps away from the GUI. The operator starts runs with `nexus model run`; the window follows and can cancel. This is
  the minimum-authority reading of "user-initiated"; a GUI composer needs a separately designed, separately authenticated
  user-intent channel (listed in §9).

## 9. Remaining blockers before tool-enabled AI integration (and for live use)

1. **No TLS termination.** `HttpSseTransport` refuses `https` (plaintext on 443 would leak the credential). Every real provider is
   https ⇒ live acceptance is impossible until a reviewed TLS client with certificate verification, SNI pinning to the sealed
   origin, and post-resolution private-address rejection (DNS rebinding) is added. Note: `rustls`/`ring` exist in the local cargo
   cache but were intentionally *not* introduced in a "model-only offline" milestone.
2. **Credential lifecycle:** one static file; no rotation/revocation runbook, no OS keyring/HSM, token lives in executor memory.
3. **No local budget/cost enforcement** (only provider-reported usage and the sealed output-token limit).
4. **No GUI-originated, user-authenticated submission channel** (§8).
5. **Executor identity.** The executor runs as the issuer identity and holds both the issuer capability and the provider token; a
   compromise of that UID is a compromise of both. A dedicated model-egress UID with a narrowed `model-redeem`-only capability
   would reduce this.
6. **Model attempts and redemption are not externally witnessed**; same-host trust anchor only (A4.4 blockers 1–8 all still hold).
7. **Tool-enabled AI** additionally needs: model-proposed actions entering only via `approval-request` (A4.2), a prompt-injection
   threat model for tool results, per-turn re-authorization, context-continuity (CCv2) bindings for multi-turn state, and a
   multi-turn grant model — none are started here.
8. `nexusd.service` was **not** changed. The production-v1 validator now **forbids** `--enable-model-pilot` (audit finding, §11b): the pilot is a development-only scope and cannot be started under the production profile.

### What `Kernel::dispatch_enabled() == false` protects (precisely)

It is a constant reported by status/readiness and the condition under which `authorize_dispatch()` (always) refuses. It guards the
**legacy, general "commands may produce effects" authority**: nothing that merely *accepts* a command can cause an effect. It does
**not** gate scoped sealed-grant dispatch — by design, `mock-e2e` (A2.3/A2.4) and now `model-only` never consulted it. Their safety
comes instead from: separate scope + flag, kernel-sealed single-use grants bound to one request/endpoint/credential, the
issuer-capability + peer-UID gates, and the absence of any tool/file/process surface in the model path. Consequently
`dispatch_enabled() == false` says nothing about whether text inference is possible; `status.modelPilotEnabled` does.
