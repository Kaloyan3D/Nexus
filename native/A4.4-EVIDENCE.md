## 2. Production security profile `production-v1`

`--security-profile production-v1` (validated before any file is touched; `--validate-config-only` checks and exits).
Requires: `--trust-mode shadow-test`, `--allowed-uids`, `--socket-group`, `--witness`, `--cap-handoff`,
`--cap-handoff-gid`, `--approver-cap`, `--approver-uids`, `--approver-cap-gid`, `--workspace-bases`,
`--external-witness`, `--external-witness-uid`, `--require-independent-approver`, `--require-human-approval`,
`--require-external-witness`; `--enable-process` ⇒ `--require-kernel-resource-limits`.
Forbids: `--allow-nonindependent-approver-test-only`, `--witness-adopt-legacy`, env `NEXUS_TEST_WRITE_CRASH_AT`,
`NEXUS_WITNESS_FAULT`, `NEXUS_TOOLS_OFFLINE_*`, root euid, any uid overlap among daemon/issuer/approver/witness.
Latched per store (`profile-downgrade-refused` for writes/process; read-only start preserved). The witness takes
`--production`, forbidding its fault injector and same-uid mode.

Fresh-store protection: a fresh DataRoot started **with** the profile cannot run without the whole contract
(`multuid_production_profile_refuses_…` (f): no store/socket created). A fresh DataRoot started **without** the
profile is legacy mode — the binary cannot defend against its own launcher. **Enforcement requires a root-owned
unit file that always passes the flag** (`deploy/nexusd.service`); a same-user launcher is not a security authority.

## 4. Systemd verification (Phase 2)

Executed: `deploy/systemd-user-integration-test.sh` against the real **user** manager with transient
`nexus-a44-*` units (removed afterwards; no existing service touched). **10/10 PASS**:
witness starts under `NoNewPrivileges/PrivateTmp/ProtectSystem=strict/ProtectHome/ReadWritePaths`;
RuntimeDirectory mode 0750; key 0600 under `UMask=0077`; daemon ordered after and `Requires=` witness;
health under the same sandbox; restart after SIGKILL by `Restart=on-failure` (stale socket reclaimed);
stopping the witness stops the daemon; `production-v1` with incomplete configuration exits non-zero and creates
no socket or store; violation logged. Finding: `PrivateTmp=yes` + state under `/tmp` fails with `226/NAMESPACE`
(state must live outside `/tmp`).

**Not verified (explicit):** `User=`/`Group=`/`SupplementaryGroups=` with distinct accounts; system-manager
`Delegate=yes` cgroup delegation to the daemon for kernel-enforced limits; RuntimeDirectory ownership/group chgrp
sequence as `nexusd`; real boot ordering; multi-service restart interaction under a system manager.
`deploy/nexusd.service` and `deploy/nexus-witness.service` were rewritten (profile flags, `Requires=`, no
`Environment=`, `RestrictAddressFamilies=AF_UNIX`, empty capability set) but are **configuration, not a tested
production deployment**.

## 6. Sandbox (Phase 4)

Host run (real systemd user scope + bubblewrap 0.13 + seccomp): `sandbox_a34` **25/25 passed, none NOT RUN**,
`preflight: kernel_enforced_limits=true, seccomp=true`. Covered: host filesystem and credentials invisible,
host writes fail, `/proc`/`/sys`, network (incl. host loopback) unreachable, env/fd non-leak, privilege
escalation syscalls EPERM, fork bomb contained/reaped, memory exhaustion stopped, CPU/wall bounds, output flood
bounded, whole-tree kill on cancel/revoke, daemonized grandchildren reaped, concurrent isolation, fail-closed
when isolation unavailable, malicious build script, kernel-enforced aggregate memory and pid limits,
`RLIMIT_NPROC` scoping, x32/compat ABI bypass, writable procfs/dev controls, read-only toolchain mounts, plus the
new **nested namespace creation via `clone(CLONE_NEW*)`** (EPERM; nested user ns ENOSPC from the user-ns limit).
Polling-backend worst case is measured and labelled (budget 64 MiB, observed peak 75 MiB).

In the userns multi-UID harness `--require-kernel-resource-limits` is refused (`sandbox-unavailable`) because no
delegated systemd scope exists for the daemon identity: **gate BLOCKED there, fail-closed behaviour verified**;
the process e2e then ran on the labelled polling backend.

Seccomp review (honest limits): a deny-list of ~48 syscalls with arch check (non-x86_64 → kill), x32 kill,
`clone3`→ENOSYS. It is not an allow-list. Unfiltered notable surface: AF_NETLINK/AF_PACKET/AF_ALG socket
creation (empty netns limits reach), `seccomp`/`prctl`/`landlock_*`, `pidfd_*`, `fanotify_init`, `mknod`,
`lookup_dcookie`, `modify_ldt`, `memfd_create`. Namespace escape via `clone` flags is already refused empirically.
Unsupported architectures are rejected (preflight problem ⇒ daemon refuses processes), not silently weakened.
Offline Cargo cache isolation: covered by A3.5 suites (single-owner, verified, read-only) and unchanged.

## 7. Human approval production gate (Phase 5)

Probed, not implemented. Facts: `polkitd` active; the user's session runs a KDE polkit agent; `pkcheck`
present; PAM modules available are `pam_unix` only; no FIDO/U2F tooling or token present. Assessment:
- polkit/PAM re-authentication proves knowledge of an account password to an agent in the *user's* session; it does
  not prove presence, the approver UID has no desktop session/agent, and any same-UID process can invoke the check
  or contest agent registration. It cannot be exercised non-interactively and was **not** implemented as a factor.
- FIDO2/WebAuthn user-presence would be a real factor but requires a token/libfido2 that is absent here.
Result: human-presence verdict **PARTIAL**; GUI approvals and autonomous execution stay **DISABLED**. No simulated
factor was added. Harness approver interaction in tests is labelled TEST-ONLY.

## 8. Integrated offline E2E (Phase 6)

`multuid_integrated_offline_e2e_under_the_production_profile` (real UIDs, witness UID 20007, profile on):
propose (issuer) → daemon-authored request/diff → approver review → **deny** (execution refused) → propose →
approve (journal already fully witnessed at response time) → wrong content refused → exact execution → second
use refused → local counts == witness counts, `verified` → **expiry** (decide refused) → **revocation** (exec
refused) → **restart** (approved-unconsumed lapses, `verified`, profile reported) → **witness outage**
(`witness-unavailable`, authority refused, health OK, bystander `peer-unauthorized`, untrusted EACCES) → same
witness identity restarted: `verified`, pending un-acked request withdrawn, new proposal executes, counts equal →
**stale lease** (new generation; old approval cannot execute; file unchanged).
`multuid_sandboxed_process_under_approval_and_witness`: `proc.run cargo check --offline` approved, argv change
refused, executed once in the sandbox (ok=true, polling backend, labelled), second use refused, approval
`consumed`, journals fully witnessed, `verified`.
`multuid_production_profile_refuses_incomplete_downgraded_and_test_only_starts`: profile dropped (downgrade
refused), test-only approver flag, adoption flag, witness config omitted, `NEXUS_WITNESS_FAULT` in env, fresh
store with incomplete profile (no files created), read-only start still possible.

## 9. Findings

Confirmed defects fixed in A4.4 (each with regression tests; the profile tests assert the refusals directly):
1. **No enforced production contract**: a fresh DataRoot could start writes/process without human approval,
   witness or kernel limits (latches only protect after first start). → `production-v1` + store latch.
2. **Test-only knobs reachable in a production witness**: `NEXUS_WITNESS_FAULT`/`--allow-same-uid-test-only`
   were honoured unconditionally. → witness `--production`; profile forbids the env in the daemon.
3. **Legacy adoption reachable under production**: now forbidden by the profile (offline migration step only).

No further exploitable defect was found in the integrated path. One sandbox hardening item (clone flag filter)
was evaluated and found redundant empirically (kept as a regression test).

## 11. Remaining attack surface and blockers

Production blockers: (1) human presence not established (needs FIDO/trusted display); (2) no external trust anchor —
root or witness-UID compromise defeats the witness; (3) real system-manager deployment with distinct `User=`
accounts and delegated cgroups unverified; (4) rootful suite blocked; (5) receipts and controller intents are not
witnessed; (6) no online credential rotation/revocation or witness key backup/reset runbook; (7) seccomp is a
deny-list; (8) profile enforcement depends on a root-owned unit that always passes it.
Accepted/documented limitations: unacknowledged tail entries may be removed undetectably (they authorized
nothing); history before first anchoring is unwitnessed; same-UID hostile module inside issuer/approver; pending
un-acked request blocks an identical retry until revoked/expired; list/history anchoring is best-effort.
Hardening recommendations: seccomp allow-list; deny AF_NETLINK/AF_PACKET/AF_ALG in the sandbox; clone-flag filter
as defense in depth; periodic independent verifier; replicated witness state; mandatory-access-control policy.
Environment limitations: 20 baseline JS suites need `pwsh`; userns harness lacks delegated scopes.

## 12. Conditions for a restricted AI pilot (attended lab only)

Allowed: offline, single-host, operator-attended terminal approval, `production-v1` with a root-owned unit,
processes only where preflight reports `kernel_enforced_limits=true`, AI output reaching the system only as
*proposals* through `approval-request` (AI-initiated execution remains disabled in code). Not allowed: unattended
operation, GUI approvals, shared/multi-tenant hosts, network-capable tools, legacy stores without adoption review.

## 13. Final consistency pass (before commit)

Finding (confirmed, fixed): `deploy/nexusd.service` runs `ExecStartPre=/bin/chgrp nexus-approver …` and passes
`--approver-cap-gid nexus-approver`, but did not list `nexus-approver` in `SupplementaryGroups=`. The daemon can
only `chgrp` to groups it belongs to, so the shipped unit would have failed at start. Fixed; regression test
`units_a44::units_agree_on_witness_identity_socket_ordering_and_group_membership` (verified to FAIL without the fix).

New `units_a44.rs` (configuration checks only, NOT a systemd deployment test): the shipped `nexusd.service`
ExecStart enables `--security-profile production-v1` and passes the daemon's own `validate_production_v1`;
`nexus-witness.service` enables `--production` and no test-only flag; neither unit has `Environment=`; both
agree on the witness socket; `Requires=`/`After=`/`Before=` are consistent; every chgrp/credential group is a
supplementary group; neither unit runs as root and the two users differ; every test-only flag and environment
variable is rejected by the validator. `Kernel::dispatch_enabled()` is unchanged (false).

### Standing warning

A fresh DataRoot started by an untrusted or same-user launcher WITHOUT `--security-profile production-v1` runs
in legacy mode and is outside the enforced production policy: this binary cannot defend against its own
launcher. The profile is enforceable only through a root-owned unit file that always passes it. Requesting the
profile with unmet requirements refuses before any file is created (tested), and a profiled store refuses
writes/process when later started without it.
