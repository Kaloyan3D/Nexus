# A5.4 Live acceptance runbook (OpenCode Go, `muse-spark-1.3-contributor`)

Live traffic is **disabled by default**. A credential file, a Registry entry, a verified route or a passing mock run is not authorization. Two operator authorizations are required, each single-use, each created by you locally. The sequence below was executed once for the A5.4 smoke test (see `native/A5.4-EVIDENCE.md`); repeat it only with fresh authorizations.

## Exact requests

**Route verification (billable, once)** — `scripts/Verify-NativeOpenCodeGoRoute.cjs`, 5 requests, all with `authorization`, `x-opencode-session: nexus-registry-probe-opencode-go-native`:
1. `GET  https://opencode.ai/inference/go/v1/models`
2. `POST https://opencode.ai/inference/go/openai/v1/responses` — synthetic text probe, `reasoning.effort=low`, `max_output_tokens=1024`
3. `POST …/responses` — same body, `stream=true`
4. `POST …/responses` — synthetic `probe_echo` tool-emission probe (Registry role `muse_main` requires `toolCalling`, so the route must prove it), `max_output_tokens=1024`
5. `POST …/responses` — stateless tool-result continuation (`function_call` + `function_call_output`), `max_output_tokens=1024`

No retries; first failure stops it. On success it attests the connection and binds `engineering-v2` to the route in the isolated Registry only.

**Acceptance (billable, once)** — through `nexus intent submit` → broker → Controller → Registry → Kernel grant → Rust executor:
`POST https://opencode.ai/inference/go/openai/v1/responses`, body keys exactly `model, input, stream, max_output_tokens, reasoning`; headers `authorization`, `x-opencode-session`, `user-agent: nexus-native-model-only/1`; prompt `Reply with exactly: NEXUS_NATIVE_OK`; `max_output_tokens` = the authorized ceiling (512 in the smoke test; a reasoning model can spend 128 entirely on reasoning and return `incomplete`); **no tools**.

## Operator commands (you run these)
```sh
cd ~/Projects/Nexus
export A54_HOME=$HOME/.nexus-a54
sh native/deploy/a54-dev-instance.sh prepare              # offline: dirs + Registry records

# 1. credential from the existing OPENCODE_API_KEY (process env first, then repo .env; parsed, never printed)
sh native/deploy/a54-dev-instance.sh credentials

# 2. route-verification authorization (5 billable requests) and run
node scripts/Verify-NativeOpenCodeGoRoute.cjs authorize --data-root $A54_HOME/registry --acknowledge-billable --expires-in-secs 900
node scripts/Verify-NativeOpenCodeGoRoute.cjs verify --data-root $A54_HOME/registry --credentials $A54_HOME/credentials.json

# 3. start the dev instance (production-v1 untouched)
sh native/deploy/a54-dev-instance.sh start

# 4. acceptance authorization (ONE billable request)
printf '%s' 'Reply with exactly: NEXUS_NATIVE_OK' > $A54_HOME/prompt.txt
native/target/debug/nexus-broker authorize-live --state-dir $A54_HOME/broker \
  --provider opencode-go-native --model muse-spark-1.3-contributor \
  --prompt-file $A54_HOME/prompt.txt --max-output-tokens 512 --expires-in-secs 900 --acknowledge-billable
```
Before authorizing and again before submitting, confirm the broker is the installed build (`sh native/deploy/a54-dev-instance.sh check` → exit 0; exit 3 = STALE, stop/start first; `authorize-live` and the live gate also refuse a stale broker). `start` refuses while an instance is alive; `stop` only signals processes whose command line names `$A54_HOME`.

Then tell the agent "authorized": it submits once with `nexus intent submit` (same exact prompt, `--max-output-tokens 512`, `--model opencode-go-native/muse-spark-1.3-contributor`) and reports the outcome. Do not run the prompt yourself; a prompt with a trailing newline would have a different digest.

Note: `printf '%s'` writes the prompt without a trailing newline; the agent submits the identical string.

## Safety properties
Records are `0600`, create-new, consumed by rename before any network use / grant issuance; absent, mismatched, expired, loose-permission or consumed records refuse with nothing sent; a second call needs a new record; no automatic retry; uncertain submissions are never resent; endpoint pinned in Rust; no model fallback.
