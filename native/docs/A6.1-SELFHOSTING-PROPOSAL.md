## 1. The task (exact text)

> In `nexus-client/src/intent_client.rs`, add a `#[cfg(test)]` unit-test module (the file has none) that covers two existing public functions without changing any non-test code: (1) `default_broker_socket()` — the `NEXUS_BROKER_SOCKET` override wins, an empty override is ignored, otherwise `$HOME/.nexus/broker.sock`, and with neither set `/tmp/nexus-broker.sock`; (2) `fresh_key(prefix)` — starts with `prefix-`, two calls differ, and the result is accepted by the intent idempotency-key rule (8..128 characters of `A-Za-z0-9._:-`). Environment variables are process-global, so serialize the tests that touch them with one `static Mutex` and restore the previous values. Propose one `fs_edit` that appends the module at the end of the file, then one `cargo test --offline --locked -p nexus-client` and stop when it passes. Do not touch any other file.

Why this task: small, self-contained, independently identified (the file has no unit tests; verified), production code unchanged, deterministic validation, and it touches none of the forbidden areas.

## 6. Model session budget and limits

The Desktop's fixed limits (also the CLI values): **12 model turns · 30 tool calls · 5 edits · 5 commands · 1024 output tokens per call · 128 KiB tool results · 30 min**. Realistic need: ~6–9 turns (list, 1–3 reads of the file, 1 edit, 1 test, answer). OpenCode Go only (`opencode-go-native` / `muse-spark-1.3-contributor`); no retry, no fallback, no substitution; a limit hit ends the run and is recorded, not extended.

## 7. Tool and approval limits

Reads need no approval and are confined to the snapshot (secret-shaped paths blocked, ≤ 24 KiB per result). **Every** write and command needs your separate approval in `nexus-approver review`. Do not approve: any path other than the file above, any change containing deletions, any argv other than `cargo test --offline --locked -p nexus-client`. A second edit/test is allowed only to fix a failing test of the new module. Same-UID caveat: the approver is you in a terminal; the daemon records human presence as `notVerified`.

## 9. Rollback / rejection procedure

Nothing is applied automatically; the only artefacts are the retained working copy under `$A54_HOME/selfhost/worktrees/…` and the run record.

* **Reject:** do nothing to the repository; optionally delete the copy (`rm -rf` that directory, or the daemon's `worktree-remove`). The active repository and snapshot are untouched by construction (verify: `git -C $A54_HOME/selfhost/nexus-self status --porcelain --ignored` empty and HEAD still the pinned id).
* **Adopt (manual, by you):** save `nexus intent diff <runId>` output → `git apply --check` against the active checkout → read every line → run the host commands in §5 → commit yourself. The commit message should say the change was model-generated. No automatic commit, merge, push, installation or deployment exists in this path.
* **Abort during the run:** Desktop *Cancel run* (revokes a pending approval, kills a running command). An unanswered approval expires on its own.
