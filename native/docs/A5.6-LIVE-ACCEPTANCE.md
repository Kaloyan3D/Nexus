# A5.6 live acceptance runbook — controlled coding on OpenCode Go

**Status: BLOCKED. Nothing in A5.6 has contacted a real provider.** This runbook is *readiness only*. The A5.4 single-call records and the A5.5 `repo-inspect` session records do **not** authorize it: a `repo-code` session makes several billable provider calls whose later bodies carry source text **and build/test command output**, and it lets the model *propose* edits and commands. A session record is typed (`intentType`); an inspect record can never be spent on a coding run and vice versa.

Nothing below may be run by the agent without a fresh, explicit operator authorization for *this* run.

## What one authorized session exposes

* Provider/model: `opencode-go-native` / `muse-spark-1.3-contributor` only; endpoint pinned; no fallback, no retry.
* Up to **N billable POSTs** (one per model turn, `N = --max-turns`, ≤ 24). Each is stateless and re-sends the task, the model's own earlier tool calls and **every tool result so far**.
* **Sent to the provider:** whatever `fs_list` / `fs_read` / `fs_search` return from the *isolated copy* (redacted; hidden, VCS and credential paths blocked; each result ≤ 24 KiB), the previews of the model's own edits as it proposed them, and the **bounded tails of stdout/stderr** of the approved commands (redacted). For this acceptance the source is the **synthetic crate** created below — no credentials, no private Nexus code.
* Tools offered: `fs_list fs_read fs_search fs_write fs_edit proc_run`. `proc_run` can only be `cargo check|test|build|fmt --check` (`--offline`), `npm test|run build`, `tsc --noEmit`, in a network-less sandbox over a read-only snapshot.
* **Every `fs_write`, `fs_edit` and `proc_run` needs a separate, single-use approval by an independent approver** that reviews the exact patch/command. Without it nothing is written or run; an unanswered request expires by itself.
* Writes go to an **isolated copy** (`git clone --local`, detached at the recorded commit). Your repository is never touched. Nothing is committed, pushed or merged.
* Unconfirmed against the real provider: the streaming shape of function calls for the three *new* tool names, and how the model copes with sandbox failure output. A protocol mismatch ends the run as `failed` with nothing executed.

## Single-UID dev instance caveat (read this)

The development instance runs the daemon, broker, CLI and approver as **one OS user**, so the approver is *not* independent of the agent's own UID: the daemon starts only because the instance passes `--allow-nonindependent-approver-test-only`. In that setup a process running as you could approve its own requests. The human-in-the-loop property therefore rests on **you personally reviewing each request in the approver terminal and typing its review code** — the agent session must not run the approver tool. Genuine OS-level independence (separate approver UID/credential group) is only exercised by the multi-UID suite (`sh deploy/multuid-userns.sh a56`).

## Commands (you run these) — fish

Proposed limits for the first run (the only numbers the record authorizes; the run can be equal or tighter, never larger): **14 turns, 30 tool calls, 1024 output tokens per call, 128 KiB total tool results, 5 edits, 5 commands, 30 min**. The task text (`code-task.txt`) tells the model to inspect once, make one minimal edit, run one test, and stop; its SHA-256 is bound into the record, so any change to the text needs a new record.

**Reminder from A5.5 §11a — live multi-turn behaviour was only PARTIAL:** streamed tool calls and continuations were accepted by OpenCode Go, but that run hit its 6-turn limit with no final answer, and reasoning-item continuity across turns is *not* validated (history is stateless; reasoning items are not carried). A failure here is data, not a reason to raise limits.

### 0. Terminals

Open **two** terminals in `~/Projects/Nexus`. Terminal A is for the agent's commands; terminal B is yours, for the approver. Neither the agent nor any script ever runs the approver.

### 1. Credentials (only if `credentials.json` is missing or stale)

The key is never printed or put in a file in the repo. In fish:

```fish
set -x A54_HOME $HOME/.nexus-a54
test -s $A54_HOME/credentials.json; and stat -c '%a %U' $A54_HOME/credentials.json      # expect: 600 <you>
# only to (re)create it — reads the key silently into THIS shell's environment, then parses it out:
read -s -x -P 'OPENCODE_API_KEY: ' OPENCODE_API_KEY
sh native/deploy/a54-dev-instance.sh credentials
set -e OPENCODE_API_KEY
```

Having the key is not permission to run anything: the live gate below is a separate single-use record.

### 2. Start the isolated instance and register the synthetic repo (terminal A)

```fish
cd ~/Projects/Nexus
set -x A54_HOME $HOME/.nexus-a54
cargo build --manifest-path native/Cargo.toml
sh native/deploy/a54-dev-instance.sh stop
test -d $A54_HOME/code-base/repo; or sh native/deploy/a54-dev-instance.sh synthetic-code-repo   # synthetic crate with one FAILING test
set -x A56_CODE_SOURCE proj=$A54_HOME/code-base/repo                                       # the one registered coding source
sh native/deploy/a54-dev-instance.sh start
sh native/deploy/a54-dev-instance.sh check                                                 # must say "runs the installed binary"
set -x NEXUS_BROKER_SOCKET $A54_HOME/broker.sock
native/target/debug/nexus intent code-sources                                              # expect exactly: proj
git -C $A54_HOME/code-base/repo status --porcelain                                         # expect: empty
```

### 3. Single-use live session authorization (you decide; terminal A or B)

```fish
native/target/debug/nexus-broker authorize-live-session --state-dir $A54_HOME/broker \
  --intent-type repo-code --provider opencode-go-native --model muse-spark-1.3-contributor --workspace proj \
  --prompt-file $A54_HOME/code-task.txt --max-turns 14 --max-tool-calls 30 \
  --max-output-tokens 1024 --max-tool-result-bytes 131072 --expires-in-secs 1800 --acknowledge-billable
```

Creating this record **is** the authorization; do not create it until you intend the run. It is consumed (renamed) by the first submission, even a refused one.

### 4. Submit the `repo-code` intent (terminal A, once)

```fish
native/target/debug/nexus intent submit --type repo-code --workspace proj \
  --input $A54_HOME/code-task.txt --max-turns 14 --max-tool-calls 30 --max-tool-result-bytes 131072 \
  --max-edits 5 --max-tests 5 --max-output-tokens 1024 --follow --json | tee $A54_HOME/code-run.ndjson
```

The stream shows `tool` events and an `approval-pending` event for every edit/command. **Nothing runs until you approve in terminal B.** Do not press Ctrl-C unless you mean to cancel (cancelling stops the provider request, revokes the pending approval and kills a running sandboxed command).

### 5. Review and approve each operation (terminal B — you only)

```fish
cd ~/Projects/Nexus
set -x A54_HOME $HOME/.nexus-a54
set -l AP native/target/debug/nexus-approver --socket $A54_HOME/daemon/n.sock
$AP list                                                    # pending approvals and their ids
$AP --cap-file $A54_HOME/daemon/approver.cap review <APPROVAL_ID>
```

`review` needs a real terminal. It prints the **exact** unified diff (for `fs_edit`) or the exact argv and sandbox policy (`network: none`, read-only snapshot) for `proc_run`, plus a review code. Approve **only** by typing that code; anything else leaves it pending (it expires on its own). Expected sequence: (1) read-only calls need no approval, (2) `fs_edit src/lib.rs` — check the diff is only `a - b` → `a + b`, (3) `cargo test --offline`. Deny anything else (another file, a different program or arguments). There is no auto-approve and no `--yes`.

### 6. Afterwards (terminal A)

```fish
native/target/debug/nexus intent result <RUN_ID>
native/target/debug/nexus intent diff <RUN_ID>
git -C $A54_HOME/code-base/repo status --porcelain          # must still be empty
git -C $A54_HOME/code-base/repo rev-parse HEAD              # must be unchanged
sh native/deploy/a54-dev-instance.sh stop
```

## Safety properties (offline-verified, see `native/A5.6-EVIDENCE.md`)

* The record is `0600`, create-new, consumed by rename once, before any grant. Expired, loose-permission, mismatched, reused or wrong-type records refuse with nothing sent.
* A restarted broker never resumes a run, revokes the dead run's open approvals, and reports a write/command whose end was never journalled as `uncertain` (`tool-outcome-uncertain`) rather than guessing.
* `nexus intent cancel <runId>` stops the in-flight provider request, revokes a pending approval, and kills a running sandboxed command tree; nothing is re-sent.
* `production-v1` refuses to start with `--enable-repo-code`.
