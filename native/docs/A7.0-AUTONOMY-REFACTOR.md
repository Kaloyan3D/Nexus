# A7.0 — Autonomy-first refactor: audit, changes, evidence

Product goal: **open Nexus → open a repository → give a task → Nexus works until the task is done or it is genuinely blocked.**
Defensive mechanisms that existed to make the acceptance tests of earlier phases provable (A3–A6.1) had piled up into something that stopped normal work. This document records what was restrictive, what replaced it, what was deliberately kept, and the evidence from real OpenCode Go runs.

Nothing here is committed, pushed, merged or deployed.

## 1. Audit — what stopped real work

Every item below was *observed* (in code, or in a real run), not assumed.

| # | Restriction / fail-stop | Where | Effect on real work | Replacement |

## 2. What was kept (security baseline)

* The Kernel remains the execution authority: leases, grants, single-use approvals, journals, receipts, fences.
* Project boundary: the model works in a daemon-created isolated copy; the original is changed only by an explicit, all-or-nothing adoption (or *trusted workspace*, §4).
* Credentials never enter a sandbox; `.env`, keys, `.ssh`, `.git`, CI definitions and git hooks stay unwritable; `.git`/credential names stay unreadable.
* The sandbox: user/mount/pid/ipc/uts namespaces, seccomp deny-list, cgroup supervision, no host filesystem. The network namespace is shared **only** for install commands of a project that allows them.
* No push, deploy, publish (`npm publish`, `cargo publish`, `git push` are not programs Nexus can run).
* The **strict profile** (independent human approver, exact argv sets, read-only snapshot, manual single-use session record) is unchanged and still tested; it is selected at daemon start (`--require-human-approval …`) and never applies to interactive use. `production-v1` still forbids the autonomous flag.

## 3. Autonomous recovery and completion

* **Provider interruptions** (`send-uncertain`, `stream-partial`, `timeout`, `disconnected`, `provider-failed`, `payload-too-large`, `sse-malformed`, `tool-call-incomplete`, `tls-failed`): the turn is asked again as a **new attempt** over the same durable conversation (all completed tool results stay). The request is a pure function of that history, so re-asking cannot repeat a local effect; it only costs another provider call. Bounded exponential backoff (2 s … 60 s), circuit breaker after 14 consecutive failures, history squeezed harder after repeated failures (context overflow). Shown to the user as "Recovered from N interruptions".
* **Uncertainty is split**: an uncertain *inference request* is retried; an uncertain *local effect* is never replayed — the model is told the outcome is unknown, and for a file change to read the file again. Commands run in a hermetic sandbox without write-back and are safe to run again.
* **Daemon restarts**: connect-time failures are retried (nothing was sent); ambiguous failures retry only for read-only commands; the supervisor restarts a dead daemon *alone* (the broker and its running work stay) and the broker re-reads the new capability.
* **Broker/daemon crash**: on restart the interrupted run is closed honestly (`loop-interrupted` / `uncertain`), then **continued** in a new run: its copy is seeded with the files the old copy added/changed/deleted, the model is told what was done (from receipts) and to verify and carry on. Bounded to 3 in a chain; user-cancelled runs are never continued; `intent-resume` continues any interrupted run on demand.
* **Premature completion**: a reply that is an announcement ("Let me check…"), a long investigation that never produced a structured report, unverified changes, a failing last verification, or scratch files left behind is answered with a nudge instead of being accepted as the end (bounded).
* **Context pressure**: stale tool outputs are stubbed, oldest whole call/output pairs dropped, a receipts note kept; budget shrinks after repeated provider failures; test hook `NEXUS_CONTEXT_BUDGET_BYTES`.
* **Test hooks** (inactive unless set): `NEXUS_FAULT_INJECT_DISPATCHES=5,11` loses the *answer* of the Nth provider request after the provider really answered.

## 4. Two workflows

* **Isolated** (default): work in a copy; review the diff; "Apply to my folder…" adopts all-or-nothing.
* **Trusted workspace** (per project, Projects page → *apply automatically*): when a task completes, changed files, and the final verification did not fail or end uncertain, the patch is applied to the folder by itself (same all-or-nothing, folder-unchanged checks; recorded on the run; nothing is committed or pushed). This is honest about being "apply on completion", not "edit the folder live": the model never gets a write path into the original, which keeps the isolation and audit properties for both modes.
* **Project policy** (Projects page): *installs* (dependency installation allowed; on by default for a project opened in the Desktop) and *apply automatically* (off by default).

## 5. Tool system

`proc_run` programs: `cargo npm npx pnpm yarn node tsc python3 pip go dotnet make sh`. `sh -c` exists only inside the sandbox. Dependencies persist per project in `<home>/envs/<project>`: npm `node_modules` and .NET `obj/` are harvested after an install and mounted over the sources; Python (`PIP_TARGET`/`PYTHONPATH`), Go (`GOMODCACHE`), NuGet, cargo home/target and npm cache live in `/work/env`. Verified through the real Kernel and sandbox: npm (is-odd), pip (six), .NET restore→build→run. **Go is implemented but untested: no Go toolchain on this machine.**

## 6. Task-oriented Desktop

The task view leads with the result: a **review report** (read-only run) or the verified outcome + summary (change run), recovery and continuation notes, trusted-apply result; diagnostics stay under Details. Settings → *Advanced: run limits*; Projects → *installs / apply automatically*.

## 7. Architecture simplification — decisions

Kept (carrying audit weight, cheap now): Kernel approvals/journals, per-turn Controller attempts, the daemon policy evaluator, receipts.
Removed from the interactive path: per-operation human approval, exact-argv sets, read-only/stateless commands, protected-manifest rule, network ban for installs, 3-refusal fail-stop, completion-without-check.
Not removed (possible next steps, with the cost): the per-turn Controller bridge (one Node process per step) costs ~1–2 s per turn; the per-command source staging copy (≈ file count) is fine up to tens of thousands of files.
