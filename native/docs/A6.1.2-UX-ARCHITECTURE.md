# A6.1.2 — Focus-first Desktop: UX architecture (for review, no code yet)

Status: **PROPOSAL for your approval. Nothing here is implemented.** Base `c85c1cf` + the uncommitted A6.1.1 outcome-integrity work (`native/A6.1.1-EVIDENCE.md`). Visual mockups of the four key states: `native/docs/A6.1.2-mockups.html` (open in a browser; static, dark Nexus palette, 1280×720 laptop frames).

Hard constraints carried over: Desktop stays **unprivileged** (no approve control, no approver/issuer/provider credential, no daemon verbs); the independent approver, approval expiry, sealed grants, write scopes and session limits are unchanged; the CLI keeps working; all existing capability remains reachable; self-hosting needs explicit operator authorization and an isolated copy and never auto-adopts changes.

## 1. What the real window taught us

Observed in the actual Tauri window (A6.1 smoke test and screenshots): at a normal 1680×941 window the main column is only ~860 px because four regions compete — a 220 px sidebar, the main column, a permanently open 300 px Inspector (empty unless a *Controller* task or mock is selected — and coding runs never populate it), and inside the main column the composer, the Recent Tasks list and a seven-tab activity panel side by side. The composer alone carries `Code / File / Web / Deep Research` (all inert), `Live execution unavailable`, a mock chip, `Run Mock`, a model select, an `Ask / Inspect repo / Code in copy` toggle, a source select and `Send/Start coding` — ten controls for one action, three of them unrelated to engineering work. The top bar and sidebar add "Daemon offline", "Mock only", "Runtime disconnected", "No ledger configured" and a "Task ledger unavailable" warning that are true but about internals, not about the user's task. The result of a coding run (what changed, did tests pass) is two tabs away.

## 2. Principles and information hierarchy

1. **The task and its verified result dominate.** 2. **Progressive disclosure** — raw tool events, hashes, digests, journal receipts, provider metadata stay one click away, never the default. 3. **Contextual UI** — the screen is shaped by the run's state (idle, running, awaiting approval, completed, blocked/failed/uncertain, reopened). 4. **Security without clutter** — the approval boundary, the "model proposal is not the authoritative request" label and every unverified/uncertain state remain visible. 5. **Restrained Nexus identity** — dark neutral surfaces, purple accent, subtle borders, dense only where it earns it; no gradient dashboards, no decorative cards.

Hierarchy shown on every task screen, in this order (each level only appears when it has content):
**L1** task statement + kind + project + lifecycle · **L2** the one thing that needs the user now (pending approval, error) · **L3** verified outcome (change applied? tests passed? exit code) and changed files · **L4** plain-language progress summary · **L5** details on demand (timeline, transcript, tool calls with receipts, diff, test output, model I/O, hashes).

Vocabulary is fixed by A6.1.1: *lifecycle* ("Model completed", "Awaiting approval", "Cancelled", …) is always shown separately from the *verified outcome* ("Tests passed · exit 0", "Blocked · approval expired · not executed", "Coding outcome uncertain", "Outcome not reported"). The model's final message is always labelled **Model's summary (a claim)**.

## 4. Navigation

Primary rail (6): **Workspace · Projects · History · Models · Sentry · Settings**. Below a divider, one collapsed group **Advanced** (chevron; remembers state) containing **Diagnostics** destinations: Control Room, Controller ledger (today's Tasks), Mock runs, Runtime & broker, Model I/O. "Advanced" is also reachable from Settings and the command palette. Nothing is deleted; every current page stays addressable.

* **Workspace** — the only place work starts and is followed.
* **Projects** — operator-registered sources by identity (e.g. `synthetic-test`, later `nexus-self`): what each allows (Inspect / Code in copy), pinned commit, write scope, source disclosure, and the fixed run limits. Read-only: registering a project is an operator action on the broker, never typed in the Desktop.
* **History** — every run, filterable by kind (Ask / Inspect / Code) and verified outcome; opening one reopens the task view.
* **Models**, **Sentry**, **Settings** — as today (Settings gains an Advanced section for the diagnostics toggles).

### F. Contextual side panel

Closed by default. Opened by *View diff*, *Test output*, *Execution evidence*, *Source*, or a tool row. Tabs: **Diff** (existing classified viewer) · **Test output** (stdout/stderr tails from the `proc_run` result, untrusted-labelled) · **Evidence** (receipts: approval ids/outcomes, pre→post hashes, exit codes, journal phases, digests, lifecycle vs verified outcome) · **Source** (project identity, pinned commit, write scope, disclosure). Dismiss with ✕/Esc. ≥1440 px it docks right (~420 px); below that it is an overlay drawer, so it never steals width from the task.

## 6. User flows

1. **Ask** — Workspace idle → mode *Ask* → type → *Ask*. Running view with streaming text; completion shows the answer (no verified outcome; "text only, nothing executed").
2. **Inspect** — mode *Inspect* → project → *Inspect*. Progress summary lists reads/searches; final answer with verified/unsupported file:line references (existing citation check).
3. **Code in copy** — mode *Code in copy* → project → limits chip → tick acknowledgement → *Start coding*. Prompt fingerprint shown for live-authorized tasks. Refusals (e.g. not authorized, wrong commit pin) surface inline with the broker's code and keep the text.
4. **Review while running** — task view C; *Details* streams the timeline; *Cancel* stops provider call, revokes a pending approval and kills a running command.
5. **Pending approval** — banner D appears at the moment the broker records it; nothing has run; copy the id.
6. **Approve externally** — in a separate terminal, `nexus-approver review <id>` (shows the daemon-derived diff/argv); type the code. The Desktop only observes.
7. **Return and inspect** — banner disappears; the progress summary shows "Edit applied" with its receipt; next approval (command) appears; then outcome card E.
8. **Review completed/failed/uncertain** — card E variants; side panel for diff/test output/evidence.
9. **Reopen history** — History → open: same task view from durable records (works after app/broker restart).
10. **Self-hosting request** — Projects shows `nexus-self` with pinned snapshot commit, write scope and the disclosure; selecting it in Code mode adds a **Self-hosting** notice ("isolated copy of a pinned snapshot; changes are never applied to your repository; a single-use operator authorization record is required"). The Desktop does not and cannot create that record; a refused submission shows `live-not-authorized` with the CLI instruction. Adoption of a result remains manual (diff → `git apply --check` → host tests → your commit).

## 9. Implementation plan (each step small, independently revertable, tests with it)

1. **S1 Side panel** — add an on-demand, dismissible panel (docked ≥1440, overlay below); remove the permanent Inspector column; Inspector content reachable from the panel. *Revert:* restore the column.
2. **S2 Navigation** — six primary items + collapsed Advanced; move Tasks/Control Room/Mock runs under it; hide Files/Terminal/Preview tabs. *No page deleted.*
3. **S3 Runtime pill** — merge top-bar/sidebar health into one popover.
4. **S4 Unified composer** — segmented mode control, contextual project/model/limits/acknowledgement row, single primary button; inert chips and mock controls out. Keep every existing safety test.
5. **S5 Task view** — header + progress summary + Details; running/blocked/failed states.
6. **S6 Compact approval banner** — collapsed/expanded, sticky, same label and no authority.
7. **S7 Outcome card + panel tabs** — verified outcome card, changed files, Diff/Test output/Evidence/Source.
8. **S8 History + Recent** — History page with kind/outcome filters; compact Recent on idle Workspace.
9. **S9 Projects page** — read-only source cards (identity, pinned commit, write scope, limits, disclosure, `nexus-self` notice).
10. **S10 Responsive + real-window acceptance** — breakpoints, then visual verification in the actual Tauri app.

Each step keeps `tsc`, `eslint`, vitest, Tauri and Rust suites green; S1–S3 and S8 need no new data; S5–S7 reuse `codingOutcome`, `toolActivity` and existing Tauri commands; only S7's *Test output* needs the `proc_run` result text, which the Conversation view already carries (no new backend verb is planned; if one proves necessary it will be proposed separately).

## 10. Acceptance criteria for the real Tauri application

Verified by screenshots of the **actual window** (not fixtures-in-jsdom) at 1680×941 and 1280×720, using the A6.1.1 fixture (approved / expired / denied / liar / pending) and the real historical A5.6 run:

1. Idle: exactly one primary button; mode control + at most project/model/limits contextual controls; no inert chips; no mock controls; no empty side panel; no clipped controls.
2. Running: task header, one-line "now" status, progress summary; Cancel works.
3. Pending: collapsed banner ≤ 56 px, shows operation, target, expiry and the approver instruction; expanded view shows the proposal, restrictions, digest **and** the "not authoritative" label; no Approve/Deny control exists anywhere (DOM and source scans).
4. Completed/blocked/uncertain/reopened: the verified outcome card is visible without scrolling at 1280×720 and never green for blocked/unverified/uncertain/unreported runs; the model's summary is labelled a claim.
5. Panel: opens for diff/test output/evidence/source, closes with ✕ and Esc, overlays below 1440 px.
6. History: reopening any run after restarting the app restores the same view.
7. Advanced contains every previously reachable diagnostic page; nothing lost (migration map checked line by line).
8. Keyboard: all of the above reachable without a mouse; focus order sane; contrast ≥ AA on the dark palette.
9. No change to Kernel/broker/approval behaviour; CLI unchanged; Rust, Tauri, `tsc`, `eslint`, vitest all green.
