## 2. Phase 1 — Desktop integration audit (what was real vs fixture, before A6.1)

Path traced: Composer (`Code in copy`) → `NexusContext.sendCode` → `api.intentCodeSubmit` → Tauri `intent_code_submit` → `nexus_client::intent_client::submit` (broker Unix socket, peer-UID identity) → broker validates the source against the client's UID → `pipeline::execute` → `inspect::run(Mode::Code)` → worktree create (daemon) → Controller bridge (Registry route, publish, accept, workspace bind, dispatch authorize) → Kernel → provider turn → proposals validated → `approval-request` → wait → daemon `tool-execute` (A3 tools / sandbox). The UI follows with `intentStatus` (300 ms until a conversation exists), then `intentList` (1.5 s) and `modelRunStatus` (1 s) polling; conversation text/tool results come from `conversation_read`; the diff from `intent_diff`.

## 3. Phase 2 — what was added to make Desktop usable

* **Fixed run limits, shown before submitting.** `nexus_client::intent_client::DESKTOP_CODE_LIMITS` (12 turns · 30 tool calls · 5 edits · 5 commands · 1024 output tokens/call · 128 KiB tool results · 30 min). A Tauri command `intent_code_limits` returns them; the Composer shows them and disables Start if the backend does not report them. The Tauri submit uses exactly these; the renderer chooses none. (Pinned by `desktop_repo_code_commands_carry_identities_never_paths_or_authority`.)
* **Disclosure acknowledgement** per task (checkbox) before Start enables, in addition to the write/execute/provider disclosure. Reset after a successful submit and when switching modes.
* **Source display**: "registered by the operator; not a typed path"; source choice is a `<select>` of broker-returned identities only.
* **Approval card + page-level banner** (§4) and **fixture-independent data**: the broker now puts `operation`, `target`, a bounded `proposal` (the model's changed lines or argv), fixed `restrictions` and `createdAtMs` into the pending-approval record.
* CLI parity: the `approval-pending` NDJSON event carries the same fields; the human line names the operation and target.
* Existing components, tokens and the `Alert/Badge/Button` primitives were reused; no redesign.

## 4. Phase 4 — approval experience (unprivileged by construction)

The card shows: operation (*Edit file / Write file / Run command*), target (path or executable), the model's exact proposed lines or argv, restrictions (edits: throw-away copy only, path-confined, nothing committed/pushed/merged; commands: network disabled, read-only snapshot, no host paths/ambient credentials, bounded CPU/memory/output/time, allowlisted programs), expiry countdown or "expired — nothing ran", and the separate `nexus-approver … review <id>` command with a copy-id button. It states plainly that this is the **model's** proposal and that the approver sees the daemon-derived exact diff/argv (digest shown). There is **no approve, deny, allow or run control** (asserted for the card in tests), no input field, no approver credential anywhere in the renderer or Tauri (source-pin tests: no `approval-decide/get/request/revoke`, no `Command::new`/`std::process`, no capability reading, no `OPENCODE_API_KEY`). A graphical approver, if ever wanted, must be a separately authenticated application in the approver's own identity; embedding approval in the normal Desktop would remove the independence A4 provides and was not done.

## 6. Phase 3 — safe project selection

* **Identities only.** `intent-code-sources` returns ids per client UID; a typed id that is not registered, or not allowed for the UID, is `workspace-not-allowed`; paths are rejected by the contract. The Desktop offers a `<select>` only. Tests: contract, CLI, Tauri, vitest, multi-UID (second UID sees none and is refused).
* **Commit binding.** `--code-commit ID=SHA40` (broker) → daemon `worktree-create … expectedCommit`: the copy is made from the real HEAD and removed again if it differs from the pin; nothing is handed out and no provider call happens.
* **Operator write scope.** `--code-write-allow ID=dir/,file` limits model-proposed writes before any approval (reads remain whole-snapshot; stated in the proposal's disclosure).
* **`nexus-self`** uses `native/deploy/a61-selfhost-source.sh`: a dedicated, reproducible single-commit snapshot of one subtree (default `native/`, without `*-EVIDENCE.md`/`docs`) exported with `git archive` — tracked files only, no history, no untracked/ignored/local state, credential-shaped tracked names refused (`.env.example` explicitly tolerated). The active checkout is never a coding source (it is dirty and would be refused), the running binaries are never in scope, and each task clones the snapshot into its own directory (cross-task access is not possible: the model names no path; the workspace root digest is bound per command by the Kernel; concurrent runs get separate copies — tested in A5.6).
* Source authorization, provider-disclosure authorization (the typed single-use session record, bound to workspace id and task text hash) and each write/process approval stay three separate acts.
