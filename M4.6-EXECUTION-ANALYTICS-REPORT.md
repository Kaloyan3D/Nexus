# M4.6 — Execution Analytics & Benchmark Telemetry: Report

Status: implemented, persisted, validated end to end through the live engine bridge. **Not committed or pushed** (no authorization given). One gap is stated plainly under "Not verified".

## 1. Architecture changes

Telemetry is captured where the controller loop actually does the work, stored in a small append-only sidecar, and *derived on read*. No existing record was changed.

| Layer | Change |
|---|---|
| `nexus-model` (`sse.rs`) | Central usage normalization `parse_usage(&Value) -> (Usage, raw)`. `Usage` gained `cached_input`, `cache_write`, `reasoning`, `total`, `cost_micro_usd`, `list_cost_nano_usd` (all `Option`; absent ≠ 0). New events `UsageRaw` (numeric leaves only) and `ResponseModel` (the model the provider says answered). Handles Responses, chat-completions, Anthropic-style and the OpenCode Go `opencode.*` block. |
| `nexus-client` | `UsageDetail { usage, raw, actual_model }` on `TurnOutput`; `run_analytics(...)` client verb. |
| `nexus-broker/src/telemetry.rs` (new) | Record types, `append`/`load` (torn-line tolerant), `analyze`, `export_document`, price loading. |
| `nexus-broker/src/inspect.rs` | Writes one `Request` record per provider request, one `Tool` record per executed call, `Phase` transitions (work / verification / recovery) at real loop boundaries. |
| `nexus-broker/src/server.rs` | Verbs `intent-analytics` and `intent-analytics-export`. |
| `src-tauri` (`linux_app.rs`, coordinator) | Commands `run_analytics`, `run_analytics_export`, `run_analytics_save`; the Mac injects host platform and app version into the export; save writes `~/Downloads/nexus-run-analytics-<validated id>.json`. Capability, build.rs and authz tables updated. |
| UI | `features/analytics/RunAnalytics.tsx`, formatters in `lib/analytics.ts`, rendered in `ThreadView` and `TaskView`. |

Sources combined at read time: telemetry sidecar + `IntentRun` record (cumulative tokens, state, times) + full tool activity + engine summary. `EngineStateRecord` is untouched (MAC-protected, `deny_unknown_fields`).

## 2. Schema changes

### Sidecar `telemetry/<run_id>.jsonl`
Mode 0600, 2 MB cap (`recordCapped` is reported if hit), one JSON object per line, tag `k`:
- `Request`: ordinal, turn, provider, configured model, actual (response) model, effort, phase, start/latency/TTFT, outcome, `UsageRec { input, output, cached_input, cache_write, reasoning, total, cost_micro_usd, list_cost_nano_usd, raw }`.
- `Tool`: index, tool, status, wait ms, exec ms, exit code, command, verification class, build/test flag.
- `Phase`: phase, atMs, detail.

Unknown fields are ignored on load, so the format is forward and backward compatible. A run with no sidecar is simply a historical run.

### Export envelope `nexus.run-analytics`, `schemaVersion: 1`
Top-level keys: `schema, schemaVersion, generatedAtMs, generator, identity, run, runtime, tokens, routing, tools, verification, cost, source, missing, rules`.
- `identity`: run/thread id, controller version, intent type, permission mode, engine id/mode/effort, `host.{hostPlatform, engineOs, engineArch, appVersion}`.
- `missing[]`: `{metric, reason}` for every metric that could not be measured. Such a metric is `null`, never `0`.
- `cost`: `actual` (provider-reported), `providerListPrice` (list-price equivalent, explicitly not billed), `estimated` (only from explicit `pricing.json`), `display`. An estimate is never presented as actual; unknown is not zero.

## 3. Metric definitions

- **Exclusive categories** (sum to wall clock): model request time + tool execution + approval/permission wait + controller remainder.
- **Overlapping measures** (not additive): TTFT, build/test time, per-request latency.
- **Tokens**: cached ⊂ input; reasoning ⊂ output; noncached = input − cached; cache hit rate = cached / input; cache-write reported separately and not subtracted. `total` = input + output as normalized.
- **Tokens/s**: output tokens ÷ summed latency of requests that reported usage (end to end, includes TTFT). The first attempt at a decode-only figure produced a 1945 tok/s artifact, so the end-to-end definition was chosen and is stated in the export.
- **Reconciliation**: per-request sums are checked against the run record's cumulative totals (`tokens.reconciliation.matches`), so nothing is double counted.
- **Tool counts**: model-requested ≠ recorded call (what the controller authorized and tried) ≠ controller attempt (one provider request); all three are separate fields.

## 4. UI changes

"Run Analytics" section in run detail (thread and task views): compact summary (wall time, model/tool/approval/controller split, tokens, cache hit, cost with its source label) and an expandable detail (per-model, per-phase, per-attempt, routing, tools/commands, verification, missing metrics). States: loading, unavailable, incomplete (historical), error. Actions: copy JSON, save JSON. Uses the existing design system (`.nv-an*` classes in `layout.css`).

## 5. Provider-specific metric support

| Metric | OpenCode Go (Responses shape) | Other shapes |
|---|---|---|
| input / output / total | `input_tokens`, `output_tokens`, `total_tokens` | `prompt_tokens`/`completion_tokens`, Anthropic `input_tokens`/`output_tokens` |
| cached | `input_tokens_details.cached_tokens`, `opencode.tokens.cache_read` | `prompt_tokens_details.cached_tokens`, `cache_read_input_tokens` |
| cache write | `opencode.tokens.cache_write_5m/1h` | `cache_creation_input_tokens` |
| reasoning | `output_tokens_details.reasoning_tokens`, `opencode.tokens.reasoning` | `completion_tokens_details.reasoning_tokens` |
| actual cost | `cost` (here `0`, i.e. provider-reported zero on this plan) | when present |
| list-price equivalent | `opencode.list_cost` | n/a |
| served model | response `model` | same |

Anything a provider does not report stays `null` and lands in `missing`. TTFT is measured by the stream client and is absent for requests that ended before a first token.

## 8. Comparison with Nexus DSH metrics

**I could not verify DSH definitions.** The repository contains no DSH report, schema or metric glossary (searched for TTFT, tokens/sec, cache-hit and related terms). The mapping below is by metric name only; confirm against the DSH definitions before comparing numbers.

| DSH-named metric | Native field | Native definition / likely difference to check |
|---|---|---|
| Total runtime | `runtime.wallMs` | run start to terminal state, including approval waits |
| Model time | `categoriesExclusive.modelRequestMs` | summed request latency, TTFT included; exclusive |
| Tool time | `categoriesExclusive.toolExecutionMs` | execution only; approval wait separate; build/test is an overlapping subset |
| TTFT | `overlapping.timeToFirstTokenMs` | per streamed request; null where no token streamed; avg/min/max |
| Tokens/sec | `outputTokensPerSecond` | output ÷ end-to-end latency (TTFT included), so lower than decode-only rates |
| Input / output tokens | `tokens.input/output` | provider-reported, per request, reconciled with run record |
| Cache hit | `tokens.cacheHitRate` | cached ÷ input; null unless every request reported it |
| Tool steps | `tools.recordedCalls` (+ `modelRequested`, `succeeded`, `refusedOrDenied`) | recorded calls, distinct from model requests and controller attempts |

## 9. Known limitations
- Runs made before M4.6 have only cumulative tokens, state and tool activity; everything else is `null` with a reason.
- Time spent in two requests that overlap (none today; the loop is sequential) would need the overlapping/exclusive split revisited.
- Estimated cost needs `pricing.json` entries; none exist for the current model, so only provider-reported figures show.
- A run whose sidecar hits the 2 MB cap is flagged `recordCapped` and later requests are not recorded.
- TTFT is missing for requests that did not stream a first token (14 of 22 in the live run).
- Interrupted runs: telemetry up to the interruption is kept and reads as incomplete; a torn last line is dropped.
