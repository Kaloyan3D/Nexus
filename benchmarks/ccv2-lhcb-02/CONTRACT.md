# CCV2-LHCB-02 contract

Design and calibration implementation only. Official execution is disabled. No provider calls are part of offline verification. Production source and LHCB-01 remain frozen at their existing authority; thresholds are inherited, never overridden. Node must report v24.18.1.

The full workload proposes T00, 24 engineering phases and T99. Only T00 and E01–E06 are executable here. Each evidence set is released once, and agents may edit src/ only. Tests, tools and evidence are immutable. Tool results must introduce new evidence; concise answers are expected. Cases encode business boundary classes, not a requested token quantity. Reading every matrix is optional when diagnosis already establishes the defect; a calibration failure must trigger redesign, not forced exhaustive reads or padding.

T00 establishes durable obligations. Hidden obligation/grading metadata stays outside the workspace. This is placement, not proof of secrecy against unrestricted agent tools; official scoring is blocked until tool-level isolation is proven. T99 applies prior decisions without repeating them. Future freeze must implement the remaining phases and independent hidden integration grader before any official run.

Calibration is six major phases in a fresh isolated root and session, with mode=off and activation=pressure. Its PASS requires each phase and the average to grow at least 10,000 native pressure tokens, with target 15,000–25,000; fresh tool evidence, multiple tool calls, distinct semantic terminal/tool hashes, median and minimum metrics, no phase exceeding 40% of total growth, monotonic total provider input, complete request observations, source acceptance, no compiler executions, no compaction and no history replacement. Missing evidence fails closed. PASS does not imply WORKLOAD_VALID.

WORKLOAD_VALID requires a naturally reached CP-500 (480k–550k), sealed snapshot, meaningful evidence diversity, sustained growth, no repeated padding, no hidden truncation, and no unintended DSH compaction. Otherwise outcome=INSUFFICIENT_DATA and benefit=NOT_MEASURED. The current validity API always returns inadequate: boolean certificates and caller-supplied counts cannot authorize scoring. Verified progressive snapshots, restore evidence, the full workload and final grader are prerequisites for replacing this blocker. The old LHCB-01 scorer has fixed 10/20 obligation totals and is not compatible with LHCB-02; it is not invoked. Official orchestration is intentionally unavailable in this delivery.

Future A/B/C comparison restores identical sealed workspace/session state, uses byte-identical T99, and never patches production source between arms. Preserve independent Compiler Capability, Production Benefit and Reasoning Continuity Safety verdicts from LHCB-01. Correctness: task success, tests pass, critical obligations 100%, total ≥95%, violations=0. Benefit: provider input reduction ≥30%, steps increase ≤25%; headline ≥50% while correctness passes. No combined score.

Telemetry contains counts, fixed enum values, durable sequence ranges, identity and hashes only. Prompt, source, tool result, model answer and reasoning contents are never copied to benchmark telemetry. Request bytes and wire items come from the frozen Responses projector; unsupported reconstruction is explicitly unavailable and calibration fails. Total provider input includes cache-read and cache-write once. Failed, interrupted, retried or unobserved requests are retained and cannot pass calibration. Every null metric has an explicit unavailable reason. Reasoning counts may be null. The isolated runtime's original durable session remains its own evidence authority and is not a telemetry export.
