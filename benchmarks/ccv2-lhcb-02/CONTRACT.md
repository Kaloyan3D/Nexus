# CCV2-LHCB-02 contract

UNFROZEN / LIVE_CALIBRATION_REQUIRED. The full offline candidate is T00, E01–E24 and T99. Official execution remains disabled. Production source, LHCB-01, CCv2/DSH thresholds and acceptance ratios are unchanged. Use Node v24.18.1. No provider calls are part of offline verification.

Evidence releases are deterministic and ordered by phase-manifest.json. The agent edits src only; package, CLI entry point, verifier and evidence are immutable. Each phase has source and new incident/case artifacts. Acceptance checks intended inspection hashes, pre/post source changes, protected evidence and all prior/current behavioral tests. Complete original source/incident tool-result bytes are the current supported inspection receipt; partial or decorated outputs are not silently guessed. This is an offline receipt validator, not a claim that the live runner instruments every filesystem read. Candidate acceptance requires a supplied pre-work inventory; production durability/provenance checks remain necessary in live use.

T00 establishes obligations; hidden grading metadata stays outside the released tree. Placement is not proof of secrecy against unrestricted agent tools. T99's original prompt bytes remain unchanged and do not repeat prior rules. The candidate's final objective grader covers all obligations and integration cases using trusted host expectations and isolated candidate execution. Critical obligations must pass 100%, all obligations at least 95%, violations zero, tests PASS and task SUCCESS. Candidate grading cannot declare an official CCv2 result.

Calibration still runs only the six representative phases in a fresh native session. Its unchanged 10k-per-phase/mean floor, zero compiler work, no compaction, monotonic provider input and durable observations remain mandatory. Median/minimum and 40% maximum phase share expose weak phases and dominance. Missing native compiler decisions are unavailable, never guessed zero. Case volume or source bytes do not establish useful pressure. Diagnostics are bounded to eight examples; outputs remain concise.

WORKLOAD_VALID still requires naturally reached CP-500 at 480k–550k, a durable progressive runtime snapshot and exact restore evidence, proven fair histories, meaningful evidence diversity and tool-level grader isolation. These remain unverified, so workload/benefit APIs return WORKLOAD_INADEQUATE / INSUFFICIENT_DATA / NOT_MEASURED regardless of caller certificates. The offline snapshot utility proves byte equivalence of a supplied fixture/state/durable tree only: it has no checkpoint/pressure authority and cannot enable official orchestration. Future A/B/C use identical T99 bytes, provider/model, production sources and baseline authority, with only intended activation policy differences.

Benefit thresholds remain ≥30% meaningful input reduction, ≥50% headline reduction, ≤25% step increase with correctness passing. Preserve separate Compiler Capability, Production Benefit and Reasoning Continuity Safety verdicts. No combined score or incompatible LHCB-01 obligation totals.

Telemetry remains content-free: counts, fixed enums, durable identities/sequences and hashes; no source, prompts, answers, reasoning or tool contents. Cache-read/write count once, reasoning never double-counts input/output, failed attempts remain represented and unavailable fields carry reasons. Wire counts/bytes are frozen-projector reconstructions, not socket captures. Durable runtime evidence alone owns authoritative pressure.
