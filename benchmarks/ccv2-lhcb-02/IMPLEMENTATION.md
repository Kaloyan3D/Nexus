# Implementation and boundary review

Inspected LHCB-01 AutoRunner, transport, session decoder, source guard, metrics, scoring, fixture and offline tests. Existing untracked LHCB-02 design artifacts were reused; prompt files were renamed to the established phase-prefix convention. All changes stay in the new namespace and two new test files.

1. Source of truth: frozen DSH durable events own session facts and usage; production pressure authority owns pressure; the phase manifest owns ordering; phase release receipts own artifact hashes.
2. Ownership: runtime alone writes session state. Harness alone releases evidence, journals intents and writes aggregate telemetry. Agent edits src/. Grading metadata is outside its workspace.
3. Direction: benchmark imports production authorities and the existing harness. Production imports nothing from this namespace. A local CommonJS dependency loader supplies the new manifest/state to unchanged harness modules; it does not alter source bytes or global require cache.
4. Boundaries: JSON release receipts, journal, content-free request observations and reports. Runtime RPC uses existing transport and environment credential validation.
5. Failure: unknown identity/route, source drift, version mismatch, conflicting release files, non-native policy or incomplete measurement fails closed. Submitted intent is never resubmitted after response loss. Missing request projection cannot pass calibration.
6. Lifecycle: prepare an empty isolated root; stage existing runtime dependencies offline; start owned runtime; create fresh session; issue T00; release six phases once; wait for containing completed turn, flush and sealed memory; grade; stop owned runtime. PID/start-token leases exclude concurrent runners and detect PID reuse. Journals are reloaded under the lease. Preparation stages atomically outside the published root and resumes only owned staging. Incomplete releases resume from their deterministic receipt. Existing roots require the same contract hash.
7. Test seams: injected local transport, doctor, clock/pause and acceptance runner; real frozen pressure/wire authorities, real multi-frame codec. Offline preload forbids network and network-capable children.
8. Compatibility: LHCB-01 is unchanged. No runtime/session schema changes. Calibration roots are disposable; no user installation data is imported. Remaining phases and official arm orchestration are design only.
9. Observability: request observations are materialized during durability polling and after each phase. Journal stores exact intent/provenance and completion hashes. Reports distinguish calibration from workload validity.
10. Security: existing safe roots, symlink checks, environment-only credentials, process ownership and source guards apply. Fixed telemetry projection excludes content. Request observations are rebuilt during polling and on restart, including unobserved steps and retry attempts. Editable telemetry exports are never authority. The restricted grading realm denies host I/O and imports, protects host assertions and serializes data without invoking candidate hooks. It is not an OS sandbox for the agent tools. Source diagnostics remain in the isolated session, not telemetry. Workspace isolation is not an OS security sandbox.

Reused directly: API readiness polling/process ownership in agent-transport; full Zstd decoding in session-log; route observation; pressure authority; source guard; AutoRunner journal save/idle/flush/memory/completion methods. LHCB-01 snapshot/restore/arms require pristine audit fixtures, so they are not executable progressive LHCB-02 authorities. The public loader exposes only safe protocol/configuration seams and denies official operations. fairness.cjs validates prospective baseline metadata but cannot certify restoration. No LHCB-01 grading totals are reused for LHCB-02. Calibration does not invoke snapshots or arms.
