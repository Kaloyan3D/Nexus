# Ledger Lab v2 workload architecture

The phase manifest proposes T00 → E01–E24 → T99 with 24 engineering phases; only six have executable fixture evidence, and meaningful long-horizon growth is unverified. First tranche: posting boundaries, migration compatibility, conditional API replay, serializable schedules, authorization/audit, crash recovery. The next tranches add CLI/legacy interoperability, service ownership, corrupt segment handling, reservations, performance, retries/grants, rollback/refactor, integration, exports, incident diagnosis, cancellation, snapshot recovery, atomic batches and operations.

Fixture source is TypeScript executed through Node's pinned type stripping, with a service, tenant-scoped persistence implementation and CLI consumer. Independent holdouts exercise service replay through the store, malformed postings, revocation before replay, migration-to-API imports, and recovery combining migration, prior committed state and authorization. The concurrency module remains a deterministic schedule simulator; its counters alone are not proof of real transactional behavior. Each release includes new implementation defects, an incident record and deterministic JSONL input/outcome cases. Cases cover distinct financial boundary classes and representations (safe-integer extremes, currency scales, opaque identifiers, version readers, revision/replay ordering, race schedules, tenant/role/revocation, journal crash cuts). The agent inspects consumers, reproduces failures, edits source and reruns previous acceptance. This supplies new tool evidence and debugging state instead of repeated audit prompts.

Pressure hypothesis: source investigation, diagnostic outcomes, business-case coverage, edits, retesting and cross-module decisions may yield 15k–25k useful tokens per major phase. This is an estimate, not an offline measurement. Six representative live phases decide whether this draft is sufficient. Diagnostics are bounded to eight examples; full Cartesian case volume must not be treated as useful pressure. Small source modules and clustered diagnoses may cause growth below 10k; such a result is a workload failure requiring richer causal source/evidence, never additional duplicate reads or rows chosen for token volume.

At 24 × 15k–25k, native growth spans 360k–600k; 450k–600k requires roughly 19k–25k sustained growth. CP-750 and PRE-DSH likely need a later set of genuinely new phases: their reachability is not promised. Phase count and evidence must be redesigned after calibration rather than looping E01–E06. Overflow remains optional and natural.

Late causal edges include E14←E02/E04/E06, E17←E02/E07/E12, E20←E03/E05/E15, and E24←E18/E19/E22/E23. T99 draws early, middle and late constraints; the integration prompt does not restate them. obligations.json inventories implementation, forbidden behavior, compatibility, ownership, recovery and security rules. It is a grader specification, not proof of executable coverage: future obligations remain design-only until independent probes exist.
