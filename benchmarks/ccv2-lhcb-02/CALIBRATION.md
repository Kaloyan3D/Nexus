# Calibration protocol

Execute T00 and six major phases E01–E06 only, in a new throwaway root/session. No official benchmark is created. Source acceptance runs after each phase and reruns all previous cases. Acceptance is sealed for that source state and never upgraded by later fixes. Public verifier output is diagnostic only; the trusted host re-evaluates cases and independent probes using isolated candidate modules. Diagnostics are capped at eight examples instead of dumping the failure matrix. Evidence/tool integrity and exact prompt/RPC provenance are checked independently of model statements.

PASS requires ≥10,000 pressure growth for every major phase and average; target 15,000–25,000. Report median and minimum too; one phase may contribute at most 40% of the total. Phase summaries must match request-derived pressure. Total provider input must be monotonically nondecreasing across all requests (including T00), mode NATIVE, zero compiler executions, no compaction/pruning/replacement, unique terminal-content hashes (text only, excluding transient IDs), semantic tool-content hashes (excluding call IDs), and one fresh tool result set per phase with multiple calls. All request counts, pressure and reconstructed wire observations must be available. Null optional reasoning counts are permitted with an unavailable reason. Each request needs an ordered durable native controller decision with an observed zero compiler count; an off policy without that observation is unavailable and fails, even if the runtime normally skips logging in off mode. Failed/unobserved attempts, duplicate sequence identities, mixed histories or inconsistent cache totals fail.

FAIL below the minimum requires redesign. Neither thresholds nor acceptance criteria may be changed to pass. Do not force the model to print/consume all matrix rows, repeat successful verifiers for pressure, or lengthen answers. Useful source, incident and causal evidence must be the growth mechanism.

Offline fixture diagnostics measure deterministic artifact diversity and reproduce defects. They cannot verify live token growth. Initial live status: UNVERIFIED. Calibration cannot satisfy the official workload gate because CP-500 is not part of this run.
