# Live comparison protocol

The original LHCB-01 official APIs remain disabled for progressive fixtures. The dedicated official entry point consumes verified live calibration and executes progressive production sessions. It does not inherit the calibration or LHCB-01 state machines.

1. Truth: production session logs own request history and usage; source inventory owns correctness; natural production pressure owns checkpoint eligibility.
2. Ownership: production writes session/controller/memory state. The observer releases workload files and writes reports. Host graders alone judge candidate code.
3. Direction: official orchestration depends on production preparation/transport and pure benchmark helpers. Neither production nor calibration depends on official orchestration.
4. Boundary: only prepared identity, RPC status/flush, durable events and file bytes cross boundaries. No caller boolean enables comparison.
5. Failure: time-bounded completion; preserve interrupted roots. Invalid calibration, route drift, modified evidence, incomplete restore and missing natural CP-500 fail closed. Provider failures are reported separately.
6. Lifecycle: fresh native accumulation until CP-500; stop owned runtime; seal progressive workspace and mutable production state; independently restore that same baseline before native, production and forced continuations. Every arm receives the same remaining phase schedule and T99 bytes.
7. Tests: real namespace visibility/write checks, physical snapshot/restore equality and corruption rejection, delayed prompt completion, true grader positive/negative controls. Scripted usage never counts as live calibration.
8. Compatibility: old roots remain diagnostics. Calibration workload hash freezes prompts, fixtures, graders, graph, acceptance and production route independently from official observer implementation. Official code gets its own protocol hash. No calibration replay or migration.
9. Observability: request usage, pressure, provenance, policy decisions, correctness, baseline hashes, latency and step counts. Failed arms remain explicit; unavailable values are not invented.
10. Security: namespace exposes only workload and frozen installation, with writable workspace/data/logs; host graders, reports, receipts, other projects and host proc are hidden. Credentials remain environment-only. Graders run outside the provider runtime with network blocked.

CP-500 remains 480,000–550,000. No repeated filler phases, artificial pressure, altered thresholds or reused T99 solution may enable a checkpoint. If the finite workload ends below the band, report WORKLOAD_INADEQUATE and no scientifically valid benefit verdict. Correctness remains all critical obligations, ≥95% total, no immutable-file violations, tests PASS and task SUCCESS. Reduction and step thresholds remain frozen. Production pressure mode and forced mode are reported separately.
