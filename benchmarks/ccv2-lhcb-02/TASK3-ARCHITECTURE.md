# Full candidate boundary review

Scope: deterministic offline workload, all 24 phases and T99; UNFROZEN and LIVE_CALIBRATION_REQUIRED. Preserve E01–E06 and add actual consumers instead of renumbering completed calibration. No production or LHCB-01 modifications. Do not enable official orchestration.

1. Truth: the versioned fixture contract owns released incidents and schemas; the tenant store owns committed accounts, replay records and journal. Indexes, exports and metrics derive from that store. Durable runtime events alone own pressure.
2. Ownership: persistence alone mutates accounts. Service owns authorization, replay and domain validation. CLI/API adapters delegate mutations to service. The agent edits only src; tools/evidence stay immutable. Every engineering phase permits code changes, including review phases that implement automated review checks; there are no prose-only read-only phases.
3. Direction: interfaces consume service; service consumes domain, persistence and authorization. Migration, audit and recovery are lower layers. Late coordination consumes these seams. Module import cycles are prohibited.
4. Contracts: plain JSON documents, explicit schema versions, opaque string identities, integer minor units, injected clocks, command/result objects. Live objects and private credentials do not cross public response/audit boundaries.
5. Failures: reject unknown versions and non-transient errors without writes. Recovery stops at corrupt/prepared suffix; quarantine retains original bytes. Retries are bounded and reuse keys; revocation precedes replay. Cancellation is observed before the store commit boundary.
6. Lifecycle: fixture released once in dependency order; source remains editable across phases. Acceptance records source/protected evidence hashes and durable inspection receipts. Store transactions validate a private staged copy and publish together; failure leaves original state intact.
7. Seams: deterministic inputs, clocks and failure schedules. Performance checks count rows examined, not elapsed time. Offline candidate reconstruction and grading require neither installed packages nor network.
8. Compatibility: v1 cents documents migrate to v3 without identifier coercion or mutation; rollback retains v3 authority and derives v1 views. Index rebuild reads committed history. Atomic batch publication adds a persistence API without replacing single-post/replay behavior. Candidate roots from earlier contract hashes are incompatible and must be recreated; production roots remain untouched.
9. Observability: bounded incident examples, structured retry/recovery/audit observations and content-free stable fingerprints. Inspector reports bytes, graph distances and probe coverage with NON-AUTHORITATIVE labels; it never declares CP-500.
10. Security: tenant scope and grant revocation precede reads/replays/writes. Audit allowlists omit secrets. Trusted grader retains expected answers outside the released tree, executes candidate in the hardened restricted realm and rejects mutation. Agent-tool confinement remains unproven; no official benefit eligibility follows from this candidate.

Persistence invariants: integer-safe balances; unique replay key within tenant; revision compare-and-swap; atomic journal/account/replay publication; no partial batch; backup retained on migration rejection. The fixture is an in-memory deterministic Node application, not a database durability benchmark. Crash recovery uses explicit serialized journals and cuts, not claims about fsync. Store-level transaction invariants are checked with integration probes. Indexes serve tenant/account history lookup and remain rebuildable.
